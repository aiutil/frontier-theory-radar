## 4. 今日深挖论文

- **一句话本质：** 数据归因领域长期在**比错东西**——不是算法不够好，是评测把难度调乱了，导致没人说得清哪种算法好；CATT 先把评测做成可控的，再发现真正的修复点在**梯度本身**（nlo）与**聚合方式**（top-k），而不是新估计器。
- **底层问题：** 现有归因评测（如 FTRACE-TREX）跑在**固定的、单一设计**的数据集上，作者指出这导致结论互相打架——同一条 BM25 在某些设置里赢过影响函数，在另一些设置里又落后（文中引 Akyürek 2022、Chang 2025、Jiao 2026）。因为静态基准在多个轴上同时不同，它们**给不出诊断信号**。更糟的是，算法研究的动力被转向"把影响近似做得更快更省"，与"评测结果是否变好"脱钩。CATT 的问法因此变了：不是"哪个算法最好"，而是**"在受控条件下，归因为什么失败"**。
- **新命题 / 新方法 / 新证据：** 方法上，两步且都不是新估计器：(1) **损失选择**——把标准交叉熵梯度换成**负对数几率梯度**（nlo），即用 `-(z_y - logsumexp_others)` 衡量该 token 对正确答案的**相对**贡献而非绝对概率，从而把关键 token 从无信息 token 中顶出来；(2) **聚合选择**——不把整个文档的 token 分数平均，而是只取**分数最高的 k 个**。证据上，作者在受控数据集上给出机制级解释：真实因果证据高度局部化，平均即稀释；nlo + top-k 后 ground truth 与其他文档的分布**完全分离**（文中 Grad-Dot 例子：全 token 交叉熵 Recall@N 0.01 → 只留 top-10 token 0.30 → 只换 nlo 0.35 → **两者结合 1.00**）。
- **研究位置：** 属于"**先修尺子，再谈算法**"这一类工作，与影响力函数（Koh & Liang 2017、Park 2023、Grosse 2024、Chang 2025）的改进路线不同——它不提出新归因器，只论证**评测设计 + 两个被忽略的实现选择**就足以改变结论。与 TRAK、EK-FAC、Grad-Dot 是被评测对象而非竞争者；与外部 FTRACE-TREX 是"受控 → 外部"的推广关系。
- **工程可验证性：** **高，且今日已本地验证。** 官方仓库 github.com/Lamsheeper/catt（MIT，★1，pushed 2026-10-30）今日下载并实跑：(a) `src/catt/attribution/losses.py` 的 `log_odds` 与闭式解 `torch.allclose=True`；(b) `token_aggregation.py` 实测 mean 2.6 → top-2 5.1（恢复约 2.0 倍信号）；(c) `data/function_bindings/` 实测 5000 文档 / 100 事实 / 每事实 50 篇 / 5000 条 distractor / `queries/{25,50,100}.jsonl` 三档 / 5 种文档原型 / hop_depth 全 0。工程入口明确：`uv sync` + `catt attribute --task fb --facts 50 --docs 10 --seed 1001 --job ekfac`，但**要求 NVIDIA GPU**（fast_jl 扩展需 CUDA 12.x 工具链）。
- **趋势关联：** 值得纳入趋势雷达继续观察。
- **长尾价值：** 即便今天不做归因，"**证据高度局部化时，全局平均就是稀释**"这条抽象可迁移到我们的日志归因、检索打分与评测聚合上；同时 nlo 这个"相对贡献而非绝对贡献"的梯度定义也可能用在别处的显著性归因。

## 7. 启发

### 系统设计启发
- **凡是把多个变量绑在一起测的系统，先把变量拆开。** CATT 的全部价值来自"一次只改一个配置项"。我们自己的 benchmark 也应检查：是否存在"同时改了难度与分布"的隐藏耦合？
- **把"失败"先归因到正确的层。** 归因方法的失败可能来自算法，也可能来自评测把题出坏了。在动算法之前，先问"我们的尺子是不是同时改了太多东西"。
- **证据往往是局部的，全局平均等于稀释。** CATT 的 nlo + top-k 与今日本地实测的"top-2 恢复约 2.0 倍信号"指向同一条：聚合方式本身可能就是主要误差来源。

### Agent 工程启发
- **决策要占一个显式、可校验的位置。** ShallowDefend 把"安全决策"做成一个 token span，于是奖励可以是规则而不是模型（self-verified reward，无需 judge、无需标注）。对我们的启发是：**任何需要被检查的中间结论，都应该落成一个可解析、可被程序校验的字段**，而不是留在模型的自由文本里。
- **浅层的东西也是杠杆。** ShallowDefend 的机制论主张是"安全对齐集中在最初几个输出 token，多轮越狱利用的正是这点"。对应到我们：防御不一定要重训整个模型，**占据最关键的那一小段决策位**可能就够。

### 研发流程启发
- **论文筛选要能输出 Prompt / Skill / Checklist，而不是只停留在摘要解释。** 今日可直接落地的三条：(1) 评测前先做"变量解耦"检查清单；(2) 局部证据用 top-k 聚合而非全局平均；(3) agent 防御方案里增加"显式决策 token + 规则化自校验"这一选项，与"再训一次模型"并列。
- **论文的失败条件往往比结论更有用。** KL-DRO 那篇自述"记录变多或漂移越界时优势消失"；SpecSlot 自述 under review；Probing 自列一整节 Known limitations。**优先记录作者自己承认的边界**。

### 评测方法启发
- **"读出强"不等于"可用"。** Probing Spatial State 今日的实测数据（f3r 的 view_consistency 0.9808 但 action_dynamics 0.0133；aether 的 action_dynamics 0.0024）与论文一致：**能从特征里解出来，不等于能维持住、更新得对、或被目标驱动地使用**。我们评测 agent 能力时也应分能力层级测，而不是用一个综合分。
- **负面结论要配可核验的数据。** WxCrop 用 AUC 0.98 / Brier 0.177 / rank correlation 0.63 三种独立口径交叉验证，而不是只报一个 LLM-as-judge 分。这是我们做内部评测值得抄的规矩。
- **别把词法基线当成梯度方法的对照组。** 今日实测：BM25 在 CATT 的 fb 配置上 Recall@10 = 1.0000，加干扰项后也只降到 0.81–0.95；而论文称干扰项把梯度方法打到 0。**用 BM25 说"这事很难"是不成立的**，必须比同配置的梯度数字。

### 平台工程启发
- **推理期增强有一条零训练成本的路，但要认白盒前提。** logit PSV 完全冻结模型权重、只在输出 logits 上加可重建的高斯偏置，再按验证集奖励选择 + 投票；今日已在 CPU 上实跑其核心（确定性成员、按奖励排序、平局规则、弃答不投票）。但它靠 **vLLM 内部 logits hook**，**闭源 API 模型用不了**——这是一条只能用在自托管开放权重模型上的优化。

### 个人学习启发
- **优先读能形成研究资产的论文，而不是单纯追热度。** 今日 10 篇里只有 1 篇（CATT）达到"论文+代码+数据"三证齐备，其余各有明确缺口；把精力按证据等级分配，比按标题吸引力分配更划算。

## 10. 最终结论
- **结论：** 重点学习
- **价值类型：** 即时价值
- **原因：** 今日第一即时价值，也是今日**证据等级最高**的一篇：论文 + 官方代码 + 官方数据三证齐备（**注意：仓库本身不含已发布的归因分数文件**，作者把模型、轨迹与预计算分数放在 HuggingFace catt-bench，今日 huggingface.co 直连超时，故那部分为『待核验/暂无』）。据 arXiv 2610.40655 摘要与 LaTeXML HTML 全文（今日回原文逐字复核，143.2KB 正文可读；作者为 Northeastern University / MIT，通讯作者 David Bau）以及官方仓库 github.com/Lamsheeper/catt 的本地下载与实跑（MIT 许可，★1，created 2026-09-30，pushed 2026-10-30）：它指出了数据归因（data attribution）领域一个此前被默认掉的结构性缺陷——**归因方法的失败被『评测设计』掩盖了**。作者的论点是：现有评测同时改变多个数据集属性（文档冗余度、词汇干扰项、文档数量），因此无法归因『到底是归因算法不行，还是评测把难度调乱了』。他们提出 CATT（Controlled Attribution Benchmark）：在**完全虚构的知识**上微调 LLM，从而给出无歧义的 ground truth，再一次只改一个配置项。作者自述结论（今日不可复现）：冗余与干扰项会一致地拖垮归因性能；训练文档内的**真实因果证据高度局部化**，标准方法把整个文档的 token 分数平均掉，等于把证据稀释成噪声；把标准交叉熵梯度换成**负对数几率（negative log-odds, nlo）梯度**能把关键 token 从无信息 token 中分离出来；只聚合**分数最高的 top-k 个 token**（而非全文档平均）后，ground truth 召回率提升 **35 到 72 个百分点**；同样的 nlo 修正推广到外部 benchmark FTRACE-TREX，对 TRAK / EK-FAC / Grad-Dot 都有效，反事实重训性能最高提升 **4.9 倍**。★ 今日证据状态（**结构级与机制级已本地核验**）：官方仓库今日拉下来并实跑成功，确认了论文主张的机制确实由代码实现：(a) 用仓库自带 src/catt/attribution/losses.py 的 log_odds 函数验证 nlo 梯度闭式 —— 实测 nlo 值与 -(z_y - logsumexp_others) 逐元素 torch.allclose 为 True；(b) 用仓库自带 token_aggregation.py 验证『局部证据被平均稀释』——构造 1 个强信号文档 + 2 个平坦文档，实测 mean 聚合得 2.6、top-2 聚合得 5.1，即**仅取 top-k 即可恢复约 2.0 倍信号**（对应论文的 dilution 论证）；(c) 仓库自带 data/function_bindings/ 实测物化了论文所说的可配置轴：5000 篇文档 / 100 个事实 / 每事实 50 篇（冗余度）、5000 条 lexical distractor、queries/{25,50,100}.jsonl 三档事实数、5 种文档原型（technical_reference / practical_guide / test_suite / tutorial / mathematical，各约 714 篇）、hop_depth 全为 0。★ 今日实测的一个**与论文口径不同的重要补充**（这是今日新增的判断，论文未以此口径报告）：用仓库自带 bm25_scores 对**已发布**数据实测词法基线（Recall@N，N=10 篇 ground truth）：fb 配置下 Recall@10 = **1.0000**（facts=25/50/100 三档全部为 1.0），即**纯词法检索在无干扰项时能拿满分**；加入 5000 条官方干扰项后（fb-distr）Recall@10 降至 **0.8104 / 0.9164 / 0.9486**（facts=25/50/100）——干扰项确实让检索退化，但**退化幅度远小于论文报告的梯度方法崩溃（论文称干扰项把 TRAK 打到 0）**。含义：论文『干扰项摧毁归因』的结论在梯度方法上成立（作者自述），但在词法基线上不成立，**我们不能用『BM25 也做不到』来佐证梯度方法的必要性**；要证明 nlo+top-k 的价值，必须对比的是**梯度方法的同配置数字**，而今日无 CUDA、无微调 checkpoint，梯度臂一条都没跑。仓库 README 自带一份已发布数字示例（f50_10d_sd1001 / ekfac：grad_cos.ce_mean Recall@N 0.0900 / AUC 0.4522，grad_cos.nlo_mean 0.9995 / 1.0000），这是**作者发布的示例输出**，非本地复现。本地无法核验项：README 声明全部模型、轨迹与归因分数在 HF Hub 的 catt-bench（vtok101 / vtok101-distr / route / route-ab-l8）——**huggingface.co 本机直连超时（HTTP=000），该 Hub 是否已实际放出、模型与预计算分数是否可用，均为『待核验/暂无』**；论文的 35–72 个百分点、4.9×、0.9995/1.0000 全部为作者自述，今日不可复现。工程入口明确（uv sync + catt attribute --task fb --facts 50 --docs 10 --seed 1001 --job ekfac），但明确要求 NVIDIA GPU；fast_jl 扩展需 CUDA 12.x 工具链。
