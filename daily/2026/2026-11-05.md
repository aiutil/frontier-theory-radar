## 4. 今日深挖论文

- **一句话本质：** 投机解码的「无损分布」保证只成立于理想化的目标模型；**前沿模型用低精度权重 + 量化 KV cache 托管时，目标的 logits 本身是有噪的，而噪声随验证块内的 slot 位置增长（每 slot 约 4%）**——于是同一个 token 被编码进 KV cache 的精度，取决于它落在验证块的哪个位置。
- **底层问题：** 不是「模型不够聪明」，而是**长时程 agent 的上下文是被逐步写进 KV cache 的**，任何一个 token 一旦以低精度落盘，后续所有步骤读回的都是这个被污染过的上下文。软件工程 agent 跑几十到几百轮、几千到几百万 token，**累积的精度损失落在最关键的决策点上**。
- **新命题 / 新方法：** 论文实测 GLM-5.3（8-token DFlash 块）与 DeepSeek-V4.1-Flash（6-token DSPARK 块）：**块内第一 slot 的噪声等同于单 token 解码，越往后每个 slot 增约 4%，到最后一 slot，log-prob 偏移 > 2 nats 的出现频率接近第一 slot 的两倍**（DeepSeek 绝对噪声约为 GLM 的一半，但相对增长率相同）。方法是把 draft 模型训练成**在关键推理处「主动被拒绝」**：被拒绝的 token 由目标模型在残差采样中重采样、写入新验证块头部、后续验证从噪声最小的 slot 重启，于是**关键决策被路由到目标模型最精确的路径**。实现是**反向 DPO**——让 draft 学会偏好目标模型「应该拒绝」的那一侧表述。**目标模型、验证规则、分布保证全部不变，只改 draft**，且只训练宿主参数的 **0.06%–0.28%**。
- **研究位置：** 它把「投机解码 = 纯加速器」这个默认假设换成了「**投机解码 = 上下文精度分配器**」，属于对既有机制的重新解读 + 一层薄薄的新训练目标，不是新架构。论文位置是**工业界 + 学术联合**（Subconscious Systems Technologies / MIT / Princeton / Northeastern），实验用两个闭源托管模型与两个托管 draft。
- **工程可验证性：** **今天没有代码**（论文全文无自身 GitHub 链接，GitHub 检索 total_count=0，作者机构下的仓库实测与本文无关），**代码状态：暂无**。但它的**诊断方法是今天就能做的**：在同一前缀上重跑前向、比较 top-k log-prob 随 slot 位置的变化，**这不需要它的模型、不需要 GPU、不需要 draft 训练**。两个评测 benchmark 独立核验为公开第三方仓库：github.com/datacurve-ai/deep-swe（**实测 stars=1,884**）与 multimodal-art-projection/NL2RepoBench（**实测 stars=193**）——**这让论文的对比数字至少具备被第三方检验的条件**。
- **趋势关联：** 关联 `coding-agent` 与 `inference-serving` 两条趋势。**推断路径（明确标注为推断）**：若「上下文精度不均」在长时程 agent 上被独立复现，它会影响所有自建投机解码栈的团队，也会被「上下文工程」这条趋势吸收为一条新的工程约束。
- **长尾价值：** 全文最有迁移价值的一句不在摘要里——作者额外训练了两个**故意不部署**的「参照偏好」，实测结论是：**「模型是否去跑测试」（0.83/0.85）与「决策用什么框定」（0.59/0.635）两个偏好两个方向都可学，但「这个决策对不对」对小 draft 模型基本学不会**（最好 0.61/0.57，落在随机水平的置信区间内，中位数 0.52/0.46）。→ **「把语义正确性外包给一个小模型」这条路走不通，能外包的只有「表述框架」**——这个判据适用于任何「用小模型替大模型做判断」的方案设计。
- **启发：** **我们自己的推理栈可能已经在承受这个损耗，只是从没测过。** 论文实测的代价是**最多 2% 的解码速度**（每块期望接受 draft token 数：GLM 训练前后均 2.28，DeepSeek 2.5 → 2.46），换 DeepSWE 上 +7.0 分（GLM-5.3-nvfp4 60.6% → 67.6%）与 +4.0 分（DeepSeek-V4.1-Flash 67.8% → 71.8%）。**这个性价比说明「测量」的优先级高于「修复」。**
- **行动建议：** 今天只做一件事：**在我们的推理栈上量一次 slot 噪声曲线**（同一 prompt 重跑 N 次，逐 slot 比较 log-prob 波动），产出一个数字：「我们栈上第 k 个 slot 的噪声比第一个 slot 高多少」。**不要今天就去训反向 DPO draft**——依赖的是我们训不了的托管 draft（GLM/DeepSeek 的 DFlash2/DSPARK），且论文明确依赖 exact verification，一旦用近似验证就失效。

## 7. 启发

### 系统设计启发
- **今天最有价值的一条是「先测量，再修复」。** ASR 的机制很漂亮，但我们要抄的是它的**测量方法**——同一前缀重跑前向、逐 slot 比较 log-prob 波动。**任何「我们可能一直在承受 X」的假设，都值得先花一小时变成一个数字，而不是先花两周变成一个方案。**
- **「精度分配」是一个被忽略的设计维度。** 我们讨论上下文工程时默认了「上下文长度」与「上下文内容」，很少讨论**「上下文里的东西被写得多准」**。KV cache 的量化与托管方式决定了落盘精度——**这应该进入我们的推理栈设计清单**（与 batch、并行策略、投机解码配置并列）。
- **逆向思维可以直接当作工程杠杆。** ASR 的做法是「让 draft 故意失败」。**在我们自己的系统里，「故意失败」通常被当成故障，但它可能是一种精度控制手段**——这个思路值得迁移到 agent 编排里（比如在关键决策点强制走慢路径/重算路径）。

### Agent 工程启发
- **长时程 agent 的误差不是随步数线性累积的，而是随「落盘精度」逐步固化的。** ASR 实测块内每往后一个 slot 噪声增约 4%——**量级本身不吓人，机制才吓人**：这些噪声被写进 KV cache 后是不可逆的。
- **小模型不能承担语义正确性判断。** 今日最有迁移价值的一句来自 ASR 全文的参照偏好实验：**「决策对不对」对小 draft 模型基本学不会（最好 0.61/0.57，落在随机水平置信区间内），而「决策用什么框定」「是否去跑测试」都可学（0.59/0.85）**。→ **任何「用小模型替大模型判断」的方案，都要先问：被外包的是「表述」还是「对错」？后者必然失败。**
- **ICL circuit 给出了 prompt 设计的机制级解释：** 少样本 prompt 里**重复标签**会触发「刹车」机制不足而误导模型，**塞入不存在的标签**会因为「重复标签门控」缺失而让读出退化。**这两个现象我们遇到过但只能凭感觉解释，现在有机制了。**

### 研发流程启发
- **GUILD 的「先抓后筛」批判对我们是直接的自我批评。** 我们今天只处理了 400 篇里的 10 篇（97.5% 丢弃），而筛选发生在采集之后——**被丢弃数据的采集成本已经付掉了**。GUILD 的回路是「提议 → 采集 → 归因评估 → 回喂」，**最可抄的是「用预测性归因代替人肉判断边际价值」**。
- **作者自己披露局限性的论文，比只报喜的论文更值得存。** DNO 那篇的价值主要不在数字（8B 模型 LC 胜率 31.7% → 45.3%）而在于它列出的四条自曝：单次运行、teacher 与 judge 同源、消融用了独立配置、实用算法偏离理论。**这四条正是我们做 LLM-as-judge 时最容易糊弄过去的地方。**
- **仓库里的 results/README.md 常常比论文正文更诚实。** 今日实测 reading-why 的 README 写明**拿掉物理约束的 Poly-sim-born 变体准确率 78.98%，高于 Born Transformer 的 76.98%**——这条限定在论文正文里没有这样并置。**读仓库的结果文档是核验论文主张的高性价比动作。**

### 评测方法启发
- **我们的评测必须区分三个层次：论文摘要 / 作者自述 benchmark / 独立复现。** 今日 10 篇里**没有一篇达到独立复现**，且至少 6 篇连代码都没有。**日报里的每个数字都要标清它属于哪一层。**
- **「attention 看起来像人标的高亮词，却解释得更差」这个结论值得单独记住**（实测：attention 排名第一的词删除只改变 32% 的答案，而证据方法改变 45%，标注者高亮一致性上 attention 却与证据方法持平 0.50 vs 0.51）——**这是「可解释性外观」与「可解释性实质」分离的第一个干净案例**，对我们选归因方法有直接参考价值。
- **DNO 的消融揭示了一条评测纪律**：消融若在与主实验**不同的配置**里跑，那么「消融带来的差距」与「实现差异」「运行波动」三者无法分离。**我们的消融必须与主实验同配置、多种子。**

### 平台工程启发
- **PEARL 的判据可以直接变成我们的对齐复测清单。** 它的核心是「更持久的压制需要从更宽的失配状态中恢复」。→ **我们做完安全对齐后，是否只在干净输入上复测过？如果没有，我们可能像 SFT 一样压住了表面行为而没压住机制。** 今日可落地动作：为每个安全用例补一个「已污染状态下的恢复」测试。
- **PEARL README 里那条安全提示是可直接执行的实操红线**：执行式代码奖励需要真实外部沙箱，**subprocess 超时不是安全边界**，本地执行默认禁用。**我们任何要跑「模型写的代码」评测的设施都要抄这条。**
- **PEARL 的仓库无 LICENSE 文件**（法律上「全部权利保留」）——**今天无法判断是否可复用，标记为待核验**。我们自己的仓库若有第三方代码复用，同样要主动处理 LICENSE。
- **Icl circuit 的仓库结构值得抄**：代码（icl/）、prompt 电池（batteries/）、**已提交的实测数据（data/）**、逐图脚本（figures/）、论文源码（paper/）、**CPU 可跑的测试（tests/）**、CI workflow——**把中间数据一起提交，别人才能不重跑就核对你的结论。**

### 个人学习启发
- **优先读能形成研究资产的论文。** 今日 10 篇里，**真正值得完整精读的是 3 篇**（ASR / ICL circuit / PEARL），其余 7 篇按价值路由落到趋势、长尾或忽略——**先做价值路由，再决定是否深读**，这条纪律今天省掉了大量时间。
- **理论家的新等价性（multiaccuracy ↔ agnostic learning）今天一个数字都给不出**，但它提醒我们：**「用评测信号替代部分训练信号」在理论上有依据**——这条旁注值得存进长尾库，等我们真要做「评测即训练」时再拿出来。
- **今天最诚实的一课**：我们连续第三天在 10 篇里做选择，而这个口径今天被量化成「丢弃 97.5%」。**每天的深挖报告都应该带一句「今天的选择是在多少篇里做的」**——没有这个数字，日报会让人误以为我们看到了全部。

## 10. 最终结论
- **结论：** 重点学习
- **价值类型：** 即时价值
- **原因：** 今日第一即时价值，**是今天唯一一篇提出了一个「我们自己也踩过但从没正面测量过」的系统性失败模式、且给出可落地利用点的论文——它把 speculative decoding 从纯加速器重新定义成「上下文精度分配器」，这件事对我们只要自己在跑长时程 agent 就直接相关**。★ 核心洞见（论文全文口径，非摘要转述）：投机解码的「无损分布」保证只成立于理想化的目标模型（一个固定的前缀→分布函数），**但前沿模型不是这样托管的——低精度权重、量化 KV cache、稀疏注意力使推理输出不可逐位复现，于是目标的 logits 变成一个随计算布局而变的噪声量**。作者直接实测：**GLM-5.3 用 8-token DFlash 验证块时，块内第一个 slot 的噪声与单 token 解码完全一样，越往后每个 slot 噪声约增 4%，到最后一个 slot，log-prob 偏移超过 2 nats 的频率接近第一个 slot 的两倍**；DeepSeek-V4.1-Flash 用 6-token DSPARK 块**绝对噪声约是 GLM 的一半，但相对增长率同样是每 slot 约 4%**。→ **一句话：投机验证在分布上无损，但在数值精度上不均匀——一个
