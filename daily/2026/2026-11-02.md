## 4. 今日深挖论文

- **一句话本质：** 数据归因领域长期在**比错东西**——不是算法不够好，是评测把难度调乱了，导致没人说得清哪种算法好；CATT 先把评测做成可控的，再发现真正的修复点在**梯度本身**（nlo）与**聚合方式**（top-k），而不是新估计器。
- **底层问题：** 现有归因评测跑在固定的、单一设计的数据集上，导致结论互相打架——同一条 BM25 在某些设置里赢过影响函数，在另一些设置里又落后。因为静态基准在多个轴上同时不同，它们**给不出诊断信号**。CATT 的问法因此变了：不是"哪个算法最好"，而是**"在受控条件下，归因为什么失败"**。
- **新命题 / 新方法 / 新证据：** 方法上两步且都不是新估计器：(1) **损失选择**——把标准交叉熵梯度换成**负对数几率梯度**（nlo），即用 `-(z_y - logsumexp_others)` 衡量该 token 对正确答案的**相对**贡献而非绝对概率；(2) **聚合选择**——不把整个文档的 token 分数平均，而是只取**分数最高的 k 个**。
- **研究位置：** 属于"**先修尺子，再谈算法**"这一类工作——它不提出新归因器，只论证**评测设计 + 两个被忽略的实现选择**就足以改变结论。与 TRAK、EK-FAC、Grad-Dot 是被评测对象而非竞争者；与外部 FTRACE-TREX 是"受控 → 外部"的推广关系。
- **工程可验证性：** **高，且今日首次达到"评测层可独立复算"。** 官方仓库 github.com/Lamsheeper/catt（MIT，★1，pushed 2026-10-30）+ HF 组织 `catt-bench`（6 数据集 / 6 模型 / 1 Space）已连通。★ 今日三条独立复算结论：(a) **Figure 4 四臂逐臂复现**（含用作者自己的 token_aggregation 从 per-token terms 重建出作者未发布的 CE top-10 臂 = 0.2976 vs 论文 0.30）；(b) **配置依赖性**——fb 任务上 nlo 单独即达 1.0000，fb-distr 上 nlo 单独仅 0.0010 而 nlo+top-10 达 0.9935，**两个修正不可互换**；(c) **正文与发布数据不一致**——FTRACE-TREX 复算得 9pp→47pp（5.22×），作者发布数据与 README 也是 9±3→47±1，**但论文正文写 8%→40%（4.9×）**。仍**未能**端到端复现梯度计算（无 CUDA、无 checkpoint）。

## 7. 启发

### 系统设计启发
- **凡是把多个变量绑在一起测的系统，先把变量拆开。** CATT 的全部价值来自"一次只改一个配置项"。我们自己的 benchmark 也应检查：是否存在"同时改了难度与分布"的隐藏耦合？
- **两个"看起来都能修"的修正，边界往往不重叠。** 今日实测最硬的一条：nlo 损失修正在无干扰项数据上单独就能把 Recall@N 从 0.09 拉到 1.00，但在加干扰项后单独只剩 0.0010——**抗干扰的那一半其实是 top-k 聚合**。做方案设计时，不要把两个修正当成可以互换的开关。
- **把"失败"先归因到正确的层。** 归因方法的失败可能来自算法，也可能来自评测把题出坏了。在动算法之前，先问"我们的尺子是不是同时改了太多东西"。

### Agent 工程启发
- **决策要占一个显式、可校验的位置。** ShallowDefend 把"安全决策"做成一个 token span，于是奖励可以是规则而不是模型（self-verified reward，无需 judge、无需标注）。对我们的启发是：**任何需要被检查的中间结论，都应该落成一个可解析、可被程序校验的字段**，而不是留在模型的自由文本里。
- **浅层的东西也是杠杆。** ShallowDefend 的机制论主张是"安全对齐集中在最初几个输出 token，多轮越狱利用的正是这点"。对应到我们：防御不一定要重训整个模型，**占据最关键的那一小段决策位**可能就够。

### 研发流程启发
- **论文筛选要能输出 Prompt / Skill / Checklist。** 今日可直接落地的三条：(1) 评测前先做"变量解耦"检查清单；(2) 局部证据用 top-k 聚合而非全局平均；(3) agent 防御方案里增加"显式决策 token + 规则化自校验"这一选项，与"再训一次模型"并列。
- **论文的失败条件往往比结论更有用。** KL-DRO 自述"记录变多或漂移越界时优势消失"；SpecSlot 自述 under review；Probing 自列一整节 Known limitations。**优先记录作者自己承认的边界**。
- **"作者发布了数据"不等于"发布了结论"。** 今日实测：CATT 的发布物覆盖 47 个 cell，但 Table 16 的 EK-FAC / Grad-Dot 行**完全没放**，seed 也只有 2/8。做复现时先查"发布物的覆盖矩阵"，别默认"论文里有 = 仓库里有"。

### 评测方法启发
- **"读出强"不等于"可用"。** Probing Spatial State 的实测数据（f3r 的 view_consistency 0.9808 但 action_dynamics 0.0133；aether 的 action_dynamics 0.0024）与论文一致：**能从特征里解出来，不等于能维持住、更新得对、或被目标驱动地使用**。我们评测 agent 能力时应分能力层级测，而不是用一个综合分。
- **负面结论要配可核验的数据。** WxCrop 用 AUC 0.98 / Brier 0.177 / rank correlation 0.63 三种独立口径交叉验证，而不是只报一个 LLM-as-judge 分。
- **别把词法基线当成梯度方法的对照组。** 今日用**作者发布的** bm25 分数复算：fb 任务 Recall@N=1.0000，fb-distr 仍有 0.9852/AUC 0.9999，且 **decoy_top1 仅 3.2%**（几乎不会把干扰项排第一）。**用 BM25 说"这事很难"是不成立的**。
- **引用数字前先跑一遍作者自己的数据。** 今日发现 CATT 正文（8%→40%，4.9×）与其发布数据（9pp→47pp，5.22×）不一致。论文正文与附录/发布物冲突时，**以可复算的那份为准，并明确记录分歧**。

### 平台工程启发
- **推理期增强有一条零训练成本的路，但要认白盒前提。** logit PSV 完全冻结模型权重、只在输出 logits 上加可重建的高斯偏置，再按验证集奖励选择 + 投票。但它靠 **vLLM 内部 logits hook**，**闭源 API 模型用不了**——这是一条只能用在自托管开放权重模型上的优化。今日复核：仓库 ★8→★11，新增 `tests/` 与 `reproduce/` 目录，但**许可证仍为 none**。

### 个人学习启发
- **优先读能形成研究资产的论文，而不是单纯追热度。** 今日 10 篇里只有 1 篇（CATT）达到"论文+代码+数据+可独立复算"四证齐备，其余各有明确缺口；把精力按证据等级分配，比按标题吸引力分配更划算。
