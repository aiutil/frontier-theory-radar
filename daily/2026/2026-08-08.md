## 4. 今日深挖论文

- **一句话本质：** 构建可靠 tool-use agent 的下一个选型分叉点是'让 agent 写脚本程序化调用工具（PTC）还是逐个 JSON 调用工具'——The Bitter Lesson of Tool Calling 把这个隐性工程选择变成可实证比较的问题；而 AV-AIVAT 把'该打多少局才能可信判断 agent 强弱'从经验拍脑袋变成 anytime-valid 统计决策。
- **底层问题：** tool-use agent 有两种工具调用范式：原生 JSON（每次调用一个工具，结构化但僵化）与程序化工具调用 PTC（用脚本链式/并行调用工具，灵活但需模型具备代码能力）。业界普遍倾向其中一种但缺乏跨当前与先前模型代际、在真实世界任务条件下的系统实证。同时，一旦要把两个 agent 放一起对战评估，'打多少局才够'长期靠经验——固定预算要么浪费（结果已定还在打）要么不足（agent 还没被区分就停了），朴素 optional stopping 又破坏置信水平有效性。
- **新命题 / 新方法 / 新证据：** The Bitter Lesson（据摘要）提出在既有 benchmark 上跨模型代际、真实世界条件下系统评估 PTC vs JSON tool calling；标题致敬 Sutton 的 Bitter Lesson 暗示可能存在'简单可扩展方法胜出'的反直觉发现。AV-AIVAT（据摘要）提出 certified anytime-valid stopping：让评估在证据充足时立即停止、保证置信水平完整、声称 74x cheaper；定位为 imperfect-information game 中的 agent 评估。两者都把 agent 工程中'靠经验拍脑袋'的环节变成'有原则的实证/统计决策'。
- **研究位置：** The Bitter Lesson 处于实证评估期（跨代际 + 真实任务，系统性强），但摘要截断导致具体定量结论缺失，benchmark 名称与模型范围需正文确认。AV-AIVAT 处于方法 + 量化结果期（有 74x 量化结果 + anytime-valid 保证），但摘要截断导致 certified 技术细节缺失，基线对照与适用范围需正文确认。全部代码/benchmark 暂无待核验。
- **工程可验证性：** The Bitter Lesson 的结论可在团队任一 tool-use agent 任务上做架构级验证（对照 PTC 与 JSON 两种调用方式在自家任务上的效果）。AV-AIVAT 的 anytime-valid stopping 若开源可直接引入团队 agent 评估流程做最小验证（对比固定预算评估的局数与置信水平）。
- **趋势关联：** 与 ai-agent 主线高度相关。今天 10 篇中有 6 篇命中 agent 主线（The Bitter Lesson、AV-AIVAT、MIST、CalibForge、Resourced Authority 以及 Low Frequency Trap 的多模态评测延伸），agent 仍是绝对主线。CalibForge（对抗性 solver 校准合成 agent 任务）与昨日 Reasoning Core（50 个程序化推理生成器）形成趋势：自动合成可验证 agent 训练任务/数据正成为明确方向。MIST（选择性信任）与 Resourced Authority（计算预算治理）分别从'agent 该信什么外部信号'与'agent 该被如何治理'两个新维度扩展 agent 可靠性议题。
- **长尾价值：** The Bitter Lesson 的 PTC vs JSON 实证结论将长期指导 tool-use agent 选型；AV-AIVAT 的 anytime-valid stopping 是 agent 评估方法论长期资产；MIST 的'选择性信任四条件设计'是 RAG/agent 上下文信任评测的长期参考；CalibForge 的'对抗性 solver 校准'是 agent 训练任务自动合成的长期方法；Resourced Authority 的'计算预算自执行授权'是 agent 治理的长期机制设计参考；Optimal Agnostic PAC 是统计学习理论样本复杂度问题的经典闭合结果。

## 7. 启发

### Agent 工具调用选型的启发
The Bitter Lesson of Tool Calling 揭示：tool-use agent 在'程序化工具调用（PTC，写脚本链式/并行调工具）'与'原生 JSON 工具调用'之间存在系统性的跨代际实证差异。对构建 tool-use agent 的团队，应在自家任务上对照两种调用方式的效果，而非默认沿用其一——尤其当模型具备代码能力时，PTC 的链式/并行优势值得评估。标题致敬 Bitter Lesson 暗示可能存在'更简单可扩展的方法（写脚本）胜过更结构化但僵化的方法（JSON）'的反直觉结论。

### Agent 评估方法论的启发
AV-AIVAT 补齐了一个高频痛点：agent 对战评估中'该打多少局才够'。固定预算评估要么浪费（结果已定还在打）要么不足（agent 还没被区分就停），朴素 optional stopping 又破坏置信水平有效性。anytime-valid stopping 让评估在证据充足时立即停止且置信水平有效，声称 74x cheaper——这是 agent A/B 评估、模型竞技场、对抗评估场景都应引入的方法论。

### Agent 可靠性的两个新维度的启发
MIST 与 Resourced Authority 分别从两个新维度扩展 agent 可靠性议题：MIST 提出'选择性信任'——agent 既要能抵抗误导性外部信号又要在上下文正确时利用它，这命中 RAG/agent 上下文信任决策的核心张力（何时该信、何时不该信）；Resourced Authority 提出'计算预算自执行授权'——把 agent 治理从规则约束转为资源杠杆，使 agent 在耗尽预算前必须重新获得授权。两者共同指向'agent 可靠性不只是模型能力问题，更是信任决策与治理机制问题'。

### Agent 训练数据自动合成的趋势启发
CalibForge 与昨日 Reasoning Core 形成明确趋势：自动合成可验证 agent 训练任务/数据正成为方向。CalibForge 用对抗性 solver 校准自动合成难度合适的 terminal agent 训练任务（multi-solver calibration 针对 solver 分歧），Reasoning Core 用 50 个程序化生成器（语义评分 + 难度控制）合成可验证推理问题。'对抗性校准/程序化生成 + 可验证 + 难度可控'是 agent 训练数据合成的三个核心要求，正在取代人工标注。

### 个人学习路径的启发
今天阅读顺序建议：先精读 The Bitter Lesson of Tool Calling 把握 PTC vs JSON 的跨代际实证结论，再看 AV-AIVAT 理解 anytime-valid stopping 如何降低 agent 评估成本，最后浏览 MIST、CalibForge、Resourced Authority 把握选择性信任、任务自动合成、计算预算治理三个趋势信号。

### 对未来 6-12 个月技术趋势的启发
趋势焦点沿三条线推进：agent 工程选型从'经验偏好'向'跨代际实证（如 PTC vs JSON）'收敛；agent 评估从'固定预算拍脑袋'向'anytime-valid 统计停止（如 AV-AIVAT）'收敛；agent 训练数据从'人工标注'向'对抗性校准/程序化生成（如 CalibForge/Reasoning Core）'收敛。三者共同指向'把 agent 工程的关键决策从经验下沉到实证/统计/自动化'。
