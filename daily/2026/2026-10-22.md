## 2. 先说结论

## 4. 今日深挖论文

- **一句话本质：** MAMath-Bench（[2610.26943](https://arxiv.org/abs/2610.26943)）把 '多 agent 协作到底赚在哪' 这个问题拆成三个可测维度，然后用实验回答——答案是：过程覆盖率确实涨了，但最终答案并不总是更准，代价是推理冗余上升，且系统对推理链的细微扰动依旧脆弱。
- **底层问题：** 'existing evaluations primarily focus on the correctness of final answers in text-only settings, offering limited insight into multimodal reasoning capabilities, the reliability of intermediate reasoning steps, and robustness against reasoning errors'。也就是说，现有评测让 agent 有动机只输出一个结论，因为只有结论被检查。
- **新命题 / 新方法 / 新证据：** 方法上两件事——引入 'fine-grained milestone annotations'，让推理链的中间步骤可被判定；引入 'adversarial reasoning-chain perturbations'，专门打 'subtle structural perturbations'（换单位、改题干结构）而非只换数值。证据上是 1,003 题 × 11 类数学 × 多难度 × text/image/audio 三条负面结论。需要明确的是：这是评测口径的论文，不是新模型也不是新训练方法。
- **研究位置：** 属评测层改进论文，接的是昨日 VAG（privileged-correction contamination）那条线——同样是质疑 '现有评测能否区分真正变强与只是看起来变强'，但 MAMath-Bench 用的是过程标注 + 对抗扰动两条武器，VAG 用的是 verifier 门控。

### [When Planning Problems Become Hard for LLMs: Separating Structural Complexity from Semantic Interpretability](https://arxiv.org/abs/2610.26964)
- **为什么现在不火也值得保存：** 据摘要（arXiv 2610.26964，Comments 为 '10 pages, 1 figure, 17 supplementary pages'）：这篇的结论带两次证伪，都可迁移。(1) 结构难度不需要再训一个预测器——'the zero-training delete-relaxation heuristic h_add outperforms learned alternatives on held-out domains (mean Spearman |rho|=0.931)'，而学到的对照分别是 ridge regression 0.707、object count 0.657、episodic retrieval architecture ARC 0.400；更狠的一句是 'ARC also fails to outperform a linear model using the same features'。(2) 语义可读性是独立的一维——他们 'progressively rename predicates while preserving states, transitions, and optimal plans'，即状态空间不变只改命名，结果 'Valid LLM planning success drops from 67.5% to 40.0% between 0% and 100% renaming, while refusals remain at 0%'；'refusals remain at 0%' 这句很关键，说明模型是安静地做错而不是承认不会。(3) 结论直接落在工程上：'Hybrid routing between an LLM and a symbolic planner depends more on calibration to the target LLM's outcomes than on the structural score selected'，以及 'improving hybrid planning requires modeling LLM behavior sensitive to predicate semantics rather than developing more structural predictors'。价值路由：这不是一篇要给 LLM 加规划器的方法论文，而是一篇告诉我们 '别往哪个方向投预算' 的选型约束——domain complexity 该用 h_add 现算而不是训模型；语义敏感度才需要建模。我们的 agent 一旦接入符号规划器，这套评测口径可以直接搬。证据边界：七个 STRIPS domain、BFS 最优规划长度，属玩具设定，向真实工具链的外推需重做；h_add 的 0.931 是 mean Spearman 绝对值的均值，样本量小。代码 / benchmark / 项目页：待核验/暂无。今日动作：存长尾；若引入符号规划器，用 rename-invariance 作为必测维度。

## 7. 启发

### 评测方法启发：多 agent 的收益必须对强单模型量
- MAMath-Bench（[2610.26943](https://arxiv.org/abs/2610.26943)）给的第一条结论是 'multi-agent collaboration does not consistently improve final-answer accuracy over strong single LLMs'。它的第二条补充了另一半真相：过程覆盖率 'can substantially enhance'，但 'at the cost of increased reasoning redundancy'。这两句合起来说明——如果我们内部要保留多 agent 架构，评测记录里必须同时有最终准确率、过程覆盖率、推理 token 冗余率三个数，只看第一个数会得出错误结论。
- 第三条结论 'particularly those involving subtle structural perturbations' 是选扰动方式的直接指令：对抗扰动要换单位、换题干结构，不能只换数字。只换数字的评测是 agent 早就饱和的那部分。

### Agent 工程启发：失败反馈是一等信息，不是噪声
- Lean 4 repair（[2610.26942](https://arxiv.org/abs/2610.26942)）的整篇价值在一句话上：'information that pure sampling discards'。编译器逐条拒绝的精确错误消息，是已经被我们付过推理成本换来的结构化信号，丢掉它等于把最好的监督信号扔掉。
- 它的收益结构值得照抄到我们的重试预算分配上：'repair pays most when sampling is constrained; its return is front-loaded, with the first repair attempt capturing 84--96% of the total gain'。即修一次就够，别设计成多次迭代修复。
- 还有一条更省事的发现：'the gain comes almost entirely from shallow tactic-execution failures rather than structural errors such as type mismatches'。修复预算应该优先投给浅层、可诊断的执行失败，遇到结构性错误直接重规划。

### 选型约束启发：难度预测不必再训模型
- STRIPS 难度分解（[2610.26964](https://arxiv.org/abs/2610.26964)）是一次干净的证伪：零训练的 h_add delete-relaxation 启发式 'outperforms learned alternatives on held-out domains (mean Spearman |rho|=0.931)'，而学到的 ARC 只有 0.400、连线性基线都没跑赢——'ARC also fails to outperform a linear model using the same features'。凡是我们打算训一个 '难度/复杂度预测器' 的场合，先算一遍现成的经典启发式。
- 它还分离出了被普遍忽略的第二维：状态空间不变、只重命名谓词，'Valid LLM planning success drops from 67.5% to 40.0%'，且 'refusals remain at 0%'。模型是安静地做错而不是承认不会——这意味着失败率上升时不会有任何自我报告信号。
- 落地结论：'improving hybrid planning requires modeling LLM behavior sensitive to predicate semantics rather than developing more structural predictors'。语义敏感度才是建模对象，结构复杂度现算即可。

### 训练数据启发：自动任务合成的验证点应前移
- DataPraxis（[2610.26924](https://arxiv.org/abs/2610.26924)）与 Navalia（[2610.26887](https://arxiv.org/abs/2610.26887)）是今日最明显的一条主线：2026 下半年大家都在做 '用可自动验证的合成任务训长程 agent'。两者验证位置的差异值得记——DataPraxis 'verifying analytical results both during evolution and after task assembly'，把验证放在 workspace 演化过程中；Navalia 用 'independent LLM review and programmatic checks' 双通道查证据一致性。
- 对我们的直接用法是资产形态：DataPraxis 产出的是 '5,000 verified trajectories'（带依赖与可验证结果），不是题目集合。如果我们要自建训练数据，产物形态应当是带验证结果的轨迹。
- 两篇的分数都要打折看：DataPraxis 自述 'DataPraxis-27B achieves 55.11 on DABStep and 51.9 on JobBench, matching or surpassing frontier models such as GLM-5.2'，但对比口径（是否同 prompt / 同工具 / 同裁判）摘要未说明；Navalia 更极端——摘要列出五个 benchmark 名称（OfficeQA Pro / FinSearchComp / Finance Agent Benchmark / APEX-Agents-AA / Workspace-Bench-Lite），却一个数字都没给，'consistent gains' 无法量化。

### 成本结构启发：小模型 + 末端人工修正
- MedPAO-Assist（[2610.26913](https://arxiv.org/abs/2610.26913)）给出了第二个 'agent 不必上大模型' 的实测锚点：0.6B SLM 跑完整条流水线，峰值约 3.3GB RAM、笔记本 CPU 端到端约 31 秒，'no external API calls, or internet connectivity'。昨日 Agima 是环境侧证据，今天是业务侧证据，两者方向一致。
- 它的 'Extract-Ground-Generate + speech-driven human-in-the-loop correction' 结构与 Lean 4 repair 是同一思想的两种形态：都不让 agent 自行冒险，而是把修正环节设计成管道的一部分。
- 边界必须写清：作者只自述 'evaluate each pipeline stage individually'，未给出与云端大模型的端到端准确率对照，属 MICCAI workshop 论文。

### 工程优化启发：多目标不要先加权
- Pareto-Optimal RTL（[2610.26904](https://arxiv.org/abs/2610.26904)，已接收 COLM 2026）批的是行业通病：'aggregating multiple objectives into a single scalar reward' 导致 'difficult to simultaneously generate diverse Pareto-optimal solutions'。它改成优化整个候选集在目标空间里的覆盖（Hypervolume Contribution 奖励），自述相对 Hypervolume +13.3pp、对单目标 RL +14.4pp。
- 迁移规则：凡是我们在多个维度打分后再加权成一个数的任务（代码生成的正确性-性能-可读性，agent 的成功率-成本-延迟），加权都会塌掉一个 Pareto 面，此时应先出候选集，再让使用方 a posteriori 选。

### 多域系统启发：离线冻结 + 在线小模块
- LightCRS（[2610.26948](https://arxiv.org/abs/2610.26948)）的成本结构很干净：离线用冻结编码器 'precomputes multimodal product representations once'，在线只留 5.3M 参数的 query-conditioned cross-attention 模块，参数跨域共享，自述 HR@1 相对最强基线 +35.4% 且 per-query 延迟降低 266 倍。
- 还有一条反直觉对照值得存档：'Joint multi-domain training itself improves HR@1 by 15.2% over separately trained single-domain models'——即合并训练好过单域模型，与摘要开头 'naively merging all domains into a single VLM degrades accuracy' 并不矛盾，说明关键在合的方式而非合不合。

### 能力分级启发：借一套现成的坐标系
- Industrial Agentic AI（[2610.26941](https://arxiv.org/abs/2610.26941)）作为综述，价值在坐标系不在结论：'a unified taxonomy covering application scenarios, embodiment forms, and five capability levels' 加 'four-layer system architecture'。它的 'five capability levels' 是能力成熟度分级，可与我们现有的 '即时/趋势/长尾' 价值路由互补——一个分能力，一个分投入时机。
- 它对通用 agent 直接落地的障碍判断也值得存档：'dynamic environments, complex physical constraints, and stringent reliability requirements hinder the direct deployment of general-purpose agents'。
- 综述本身无新实验、无代码、无数据，全部结论依赖被引文献，五挑战与五层级的划分依据摘要未展开，无法核验完备性。

### 忽略纪律：相关性不足即不做深挖
- 塔吊自主施工（[2610.26899](https://arxiv.org/abs/2610.26899)）做的是 enhanced SAC 规划塔吊动作 + 运动学兜底 + 用 ChatGPT 5 更新进度与出报告，验证是挡土墙实物实验。与我们的赛道无交集，且摘要未给出任何可量化 benchmark 数字，无代码或数据入口，按价值路由保留最小索引即可，不套用深挖链路。
