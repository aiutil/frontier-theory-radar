## 4. 今日深挖论文

- **一句话本质：** TokenCast（[2609.35760](http://arxiv.org/abs/2609.35760v1)）把 LLM Agent 整次执行的 token 消耗建模为可组合的 cost model，可在执行前估计预算、随执行过程动态刷新估值——这是从'agent 跑完才知道花了多少'走向'agent 跑前就有预算 + 跑中可调控'的关键工程资产。
- **底层问题：** 当同一个 LLM Agent 执行同一个任务，token 消耗可以跨 run 变化超一个数量级——agent 根据 tool feedback / intermediate result 选择下一步，context 持续膨胀使每次后续调用的输入都变大。任务总消耗在执行前难以预测，执行中也必须随着运行动态刷新估值。问题是：能否把'token consumption'建模成可组合、可预测、可调度的 cost object？
- **新命题 / 新方法 / 新证据：** 提出 TokenCast——一个 composable cost model，可在执行前估计 token 消耗，并在执行过程中随工具反馈 / 中间结果 / 上下文增长刷新估值；目标是把 token 消耗从隐性指标变为显式可观测、预测、调度的工程对象。
- **研究位置：** 介于 LLM serving cost modeling / agent execution planning / inference scheduling 之间——不提出新模型架构，而是把'cost governance'作为 agent 运行时的一等公民；属于'agent 经济性 × runtime 治理'路线。
- **工程可验证性：** 暂无开源代码 / benchmark / 项目页链接，需打开 PDF 看 cost model 形式化、训练数据、跨 agent 框架（LangChain / AutoGen / CrewAI 等）的兼容性；复现门槛中（核心是 cost model 的形式化 + 可组合性 + 跨 agent 框架验证）。
