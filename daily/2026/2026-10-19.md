## 4. 今日深挖论文

- **一句话本质：** MLExpert（[2610.22344](http://arxiv.org/abs/2610.22344)）把 'generalist agentic model for autonomous machine learning engineering' 立为统一目标——让单个 LLM 自主决定 dataset / feature / pipeline / training config / 后续迭代，把 MLE 从 workflow 编排推到 'model-directed interaction, allowing models to autonomously organize and evolve their own ML engineering process'。
- **底层问题：** 传统 AutoML 把搜索空间做成可枚举 grid/Bayesian，workflow-driven MLE 系统需要人提前规划 dataset / feature / trainer / 迭代流程。但当 LLM 自身已经具备代码 / 阅读 / 计划能力后，是否可以让模型在每一步自行决定 '我现在要不要换 feature / 改 loss / 重采样 / 训练更长 / 重启'？如何让这种自治决策变成可观测、可评测、可治理的过程？
- **新命题 / 新方法 / 新证据：** 把 'autonomous ML engineering' 形式化为 'model-directed interaction'——LLM 不再执行固定 pipeline，而是对 dataset / feature / pipeline / training config / 后续迭代拥有完整自治权。这是对 'workflow-driven MLE' 的明确升级。
- **研究位置：** 介于 coding-agent（AIDE / AutoML-class）/ MLE-agent（MLAgentBench / KARO / MLE-Bench）/ AI4AI（自我改进 agent）之间——前者关心 'agent 能不能写代码做实验'，后者关心 'agent 能不能自治演化自己的 ML 流程'。本文的定位更接近后者，且明确以 'generalist' 命名。
- **工程可验证性：** 暂无开源代码 / benchmark / 项目页链接，需打开 PDF 看是否公开训练轨迹 / 数据集 / 基准协议；属于 agent 工程资产，复现门槛中等（核心是 prompt + scaffold + rubric + dataset / trainer interface），下游可在内部 AutoML / AutoMLOps 流水线接入 agent harness 做最小 PoC。
- **趋势关联：** 与 aiutil 长期关注的 AI4AI / agent self-improvement / coding-agent 主线直接共振——若 MLExpert 公开训练轨迹与 benchmark，会成为团队日后做 '内部 ML agent rubric' 的低成本底座；与今日 FDE-Gym（[2610.22350](http://arxiv.org/abs/2610.22350)）、T2-Z（[2610.22364](http://arxiv.org/abs/2610.22364)）、CoDA（[2610.22362](http://arxiv.org/abs/2610.22362)）、OmniVerifier-C1（[2610.22355](http://arxiv.org/abs/2610.22355)）一起构成连续的 'agent 自改进 + ambiguous-spec delivery + test-time env latent + data-policy 共进化 + graded verifier' 主线。

- **启发：** '把 AutoML 从 grid 推到 agent harness' 是 LLM 时代自然的范式迁移；'model-directed interaction' 是这一迁移的关键设计点；'generalist agentic' 与 'workflow-driven' 是这一迁移的命名区分。
