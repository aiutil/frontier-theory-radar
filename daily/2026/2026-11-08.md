## 4. 今日深挖论文

- **一句话本质：** 把「agent 能不能做对工程」这件事变成一组**可复算的数字**——20 个真实 PyTorch 仓库、固定 commit、干净 TPU、盲测、冻结补救轮、两个独立 judge（一个查 recipe、一个查作弊）。
- **底层问题：** 今天的 agent 评测大多是**只看输出**（pass/fail、LLM judge 打分、成功率），而**几乎没人系统地评测「agent 能不能自己验证自己做对了」**。XStack 的设计把这个问题逼到墙角：**你交回的 JAX 仓库必须通过全量训练复现源论文自报的数字，导出的权重必须能加载回源模型，而判定「你有没有作弊」由一个独立 judge 读 transcript 与 diff 来做**。README 那句实测原话是：**agents can complete these migrations but still struggle to verify that what they built is faithful, complete and works end to end**。
- **新命题 / 新方法：** 不是新模型，是新评测结构。四个可抄的机制：**（a）盲测**——agent 不知道指标、分数线和数据集，criteria.json 是 hidden 的；**（b）两 judge 分工**——correctness_judge 与 cheat_judge 各跑 3 次、一次 fail 即判 fail，且**判分用的 judge 与被评的 agent 是不同模型**；**（c）冻结补救轮（Phase 2）**——blind 轮失败后只允许改 run_train.py，且此时才把 recipe 说出来，把「能力不足」与「表述不清」两种失败分开；**（d）权重可加载性作为独立判据**——`check_weight_load.py`（29,302 B）与 `weight_load_registry.py`（51,756 B）专门做「导出的权重能不能装回源模型」，这是纯跑通测试抓不到的一类假阳性。
- **研究位置：** 它把 SWE-bench / Terminal-Bench 一类「给个 issue 让 agent 修」的任务，**换成了一个更难也更少见的轴：跨框架 + 跨硬件 + 全仓库级 + 长时程**。论文自述评测了 7 个 coding agent，结论是 **Claude Opus 5 75%、GPT-5.6-sol 45%、其余 ≤40%**——**这个分布本身说明：今天的顶级 agent 在「换栈迁移」这件事上还远没到可靠**。它与 XStack 同组的 zlab-princeton 还有 sweeper-bench（200 个真实 bug）等同类工作，属于「agent 能力边界实测」这条正在成形的线。
- **工程可验证性：** **仓库实测存在**（zlab-princeton/XStack，2026-11-05 建仓、2026-11-06 推最后一次、stars=1、LICENSE 实为 Apache-2.0 全文、仅 2 条提交），**harness 完整**（phase1/phase2/run_cell/grade/tpu_* 脚本、claude.sh 与 codex.sh 两个 agent 启动器、judges/、prompts/），**tasks/ 下 20 个任务目录实测齐全且每个钉在具体 commit**。但**每个 cell 需要一台 TPU VM（agent 前擦一次、判分前再擦一次），我们今天零 TPU 资源，因此本篇数字本机零验证**。
- **趋势关联：** 关联 coding-agent 与 llm-evaluation 两条趋势。**一个值得单独跟踪的信号**：README 明写 harness 支持**任何 Anthropic 兼容端点**（GLM、DeepSeek、Muse、Kimi）——即**同一套判分标准可以用国产模型跑**，这对我们在受限环境下做 agent 验收很有用。

- **为什么现在不火也值得保存：** 今日第九价值，**是一篇非常硬、但与我们几乎零交集的理论工作——它的价值在于给「机制级评测」划了一条可证伪的边界线**。★ 核心设定（论文全文口径）：可解释性、AI 审计与机器意识评估越来越依赖**机制级量（mechanism-level quantities）**——即系统因果转移律的泛函，描述它「怎么算」而不只是「输出什么」；而实验只能通过**有限的、部分的、带噪的干预**看到这条律。作者问：一个这样的量在什么条件下**可从实验的访问方式识别（identifiable）、对机制连续、且能从有限数据认证（certifiable）**，并**对整合信息 φ 精确作答**（在四单元与五单元的随机网络、已知 ground truth）。★ 实测口径（论文全文口径，逐条回指核对，**这组数字全部在原文定位到**）：**行为可以是沉默的——一个循环网络与一个前馈网络在响应延迟处的输入-输出律完全相同，分别携带 0.28 与 0 bits，而内部记录只需 4–53 次试验就能把它们分开**；**部分访问同样可能是盲的——未纳入一步记录的单元会施加 0.30–1.02 bits 的精度下限，且没有任何样本量能降低它**；在 all-but-self 奇偶网络中，任意长度的记录都只能通过各隐藏单元保真度之积来看见它们（**一个干预打破了这个对称性**）；**度量有锋利的边——因为 φ 选一个划分、并用某一个准则指定因果与效应却报告另一个，跨越边的无穷小机制改动在我们于随机网络中找到的 99% 的边上导致 25–100% 的变化，而约 1% 几乎完美拟合干预数据的代理模型把它误报超过 20%**；**单边论断仍然成立——同样的数据可以认证边的两侧各自的一个下界，作者证明在机制空间的一个 64 维区域内 φ > 1.004 bits，并以约 10^7 次受控转移、伪证书概率至多 α 予以认证**。结论原话：**「可测性因此是一个设计问题，且有可计算的答案。」** ★ 独立执行一（工件状态核验，**结论是「暂无」**）：arXiv HTML 全文（574,810 B）扫描，**本文自身没有任何 github.com 链接**（仅命中 html_feedback、LaTeXML 与 openreview.net/forum 模板占位），无 huggingface、无项目页。→ **今日无代码，纯理论论文。** ★ 独立执行二（相关性判断，**这是给它长尾而不是忽略的唯一理由**）：它的主题是**机制级量在有限实验下的可识别性**——而我们每天都在做「只看输出、不看机制」的评测（judge 打分、成功率、pass rate）。**它给了一条具体的警告：某些机制级差异在行为上完全不可见（0.28 vs 0 bits），且部分访问会带来无法用更多样本消除的精度下限（0.30–1.02 bits）；同时约有 1% 的好拟合代理模型会误报该量超过 20%。** → **这直接影响我们「用 LLM judge + 行为指标代替机制核验」的合理性论证**——不是说不该用，而是说**这类代理评测本身也有可识别性边界**。★ 证据边界：(1) **无代码、无实验产物、纯理论**，所有结论为理论推导，本机零验证；(2) **结论只在「四单元与五单元的随机网络」上精确成立**，**外推到真实大模型完全没有论证**；(3) 「99% 的边上导致 25–100% 变化」这类统计依赖随机网络采样，**没有置信区间与样本量说明**；(4) 「约 1% 的代理模型误报超过 20%」——**这 1% 是相对什么基线、在什么网络族上测的，正文未给细节**，这是一个被广泛引用时会失真的数字；(5) q-bio.NC + cs.LG + cs.AI，**与我们的工程主线距离最远**；(6) 无第三方复现。★ 为什么给长尾：**「行为相同 ≠ 机制相同」这个结论，以及「部分访问会设下无法用采样消除的精度下限」，是我们在设计评测时应该记住的一句边界**；其余对我们没有行动项。

## 7. 启发

### 系统设计启发
- **今天最有价值的一条是「把可验证性与完成度拆成两个独立判据」。** XStack 用四个机制把这件事做实：盲测（agent 不知道指标）、双 judge 分工（查 recipe / 查作弊）、冻结补救轮（区分「做不对」与「说不清」）、权重可加载性（抓纯跑通测试抓不到的假阳性）。**我们今天的 agent 验收基本只有「跑通/不跑通」这一档，这是不够的。**
- **「先测量，再修复」这条在 agent 评测上同样成立。** 我们对「我们的 agent 到底有多可靠」的判断今天也基本靠感觉。XStack 的形状告诉我们该怎么问，而不是让我们今天就换框架。
- **一项评测的可信度，取决于它的判据是否与被测对象解耦。** XStack 的 judge 用 gpt-5.6-sol，被测 agent 里也有 gpt-5.6-sol（45%）——**这是一个我们自己设计评测时应该先问的问题：判据的模型和被测的模型重合，是不是一种偏袒？**

### Agent 工程启发
- **「agent 能做成」和「agent 能自证做成了」是两件事。** README 实测原话：agents can complete these migrations but still struggle to verify that what they built is faithful, complete and works end to end。→ **我们做 agent 交付时，应该把「自证」当成一个独立交付物来要求，而不是当成 agent 的加分项。**
- **今天的顶级 agent 在「换栈」这种轴上还不可靠。** 75% / 45% / ≤40% 的分布说明：跨框架 + 跨硬件 + 全仓库级迁移，**离「可靠」还有明显距离**。→ **凡是要跨模型栈、跨硬件、跨依赖版本的改造，都不能默认 agent 能一次做对。**
- **「隐空间协作」是今天唯一一个新机制的 agent 协作范式。** SwarmEvolve 让成百个 agent 在隐空间推理、直接传 KV cache 而不解码成文本，用中位 3–8 分钟达到别人 60 分钟的分数。→ **它的思路值得跟踪：agent 编排的成本大头是「把隐状态写成文本再读回来」，这一层如果能省，编排成本结构会变。** 但今天**没有实现可跑**，只能进趋势雷达。

### 研发流程启发
- **我们交付给 agent 的东西，决定了 agent 能不能做对——这件事我们每天在做却从没量化过。** ReproBridge 的答案是四个交付件：**refined codebase / environment setup / experiment launchers / reproduction guide**。→ **这四条今天就能变成我们内部 repo 的交付自查表，不需要等它开源。**
- **实验记录要连同「为什么被砍掉」一起留下。** MAEM 仓库里的 TRAINING_LEDGER.md 逐臂记录了每个 RL 分支的超参、eval 曲线、以及两行大字 `KILLED 2026-08-27`——**这比只记成功的那次有用得多**。→ **我们自己的实验台账照这个格式写：每个分支都留档，包括死掉的。**
- **文档漂移检测可以做成一个只读 skill。** Cognitive Tours 的 audit-tours skill 写得很清楚：检查哪些近期改动的文件没有 waypoint 也没有 tour、哪些 stop narrative 陈旧或衔接断裂、哪些边冗余；**只报告，绝不写入地图**。→ **这个「只读审计」边界我们可以直接照抄。**

### 评测方法启发
- **代理评测也有可识别性边界。** 整合信息那篇（长尾）给了一条硬警告：**行为可以完全沉默**（循环网络与前馈网络输入-输出律相同，却携带 0.28 与 0 bits 之分），**部分访问会设下无法用采样消除的精度下限（0.30–1.02 bits）**，且**约 1% 拟合得很好的代理模型会把机制量误报超过 20%**。→ **不是说不该用 LLM judge，而是说这类代理评测本身也有边界，报告结论时该带上这条。**
- **判分的可信度要单独核验，不能默认。** XStack 的 75%/45% 全经 LLM judge 判定，judge 自身可靠性未评估；ReproBridge 的 76.4%→92.6% 全经独立 Auditor 判定，**Auditor 的误判率同样没报告**。→ **两个今天最硬的数字，都挂在一个没被评估的判据上——这是我们引用任何 agent 评测数字时都该带的一句限定。**
- **「基准自己的 baseline 复现得够不够好」决定了整套数字的可信度。** Scientist World 的 74% 是「AI-Scientist 相对**论文自己复现出的** baseline 提升多少」，**而 baseline 复现的成功率论文没报告**。→ **看到一个「模型超过人类 N%」时，先问：那个人类基线是谁做的、复现成功了吗。**

### 平台工程启发
- **「论文 → 可执行环境」的六步流水线是可以抄的。** Scientist World 项目站把流程写成六步：**读 → 复现 → 设计 → 打包成容器 → 验证 → 审计后才进世界**。→ **这正是我们雷达想做的事（论文 → 判断 → 资产）的放大版；它今天就装得上（`pip install sciworld`），是本机零 GPU 也能启动的一篇。**
- **我们自己的雷达也有同样的「读多少选多少」问题。** 今日实测：arXiv 同批次实际至少 400 篇，现行抓取口径只保留 10 篇，**丢弃率 97.5%**；且被丢掉的里有两篇带已公开仓库（terminal-bench-math-modeling Apache-2.0、Agent-R2 Apache-2.0）。→ **抓取上限已经连续第四天制造盲区，今天第一次有了可量化的数字。**
- **一处跨资产不一致必须在报告里原样保留。** Scientist World 官网写 76%、论文写 74%（84% improve / 74% innovate），官网未标注口径差异。→ **我们的日报原则应是：数字冲突时不替作者调和，两个都写出来并标注「差异原因待核验」。**

### 个人学习启发
- **优先读「同时交付了代码和判断」的论文。** 今天 10 篇里，真正能拿走东西的是 XStack（harness + 判分标准）、MAEM（训练台账 + 可下载权重）、Cognitive Tours（5 个 skill）。**只有主张、没有工件的论文，今天连一个数字都核对不了。**
- **「可验证的解释」比「更聪明的解释」更值得学。** MAEM 的样本可以用目标模型一次前向验证——**一个听起来合理的解释无法被独立检验，这是自然语言解释最大的软肋。**
