## 7. 启发

### Agent 经验沉淀结构化的启发
WikiSkill 把分散在 trajectory/optimization history 里的洞察结构化沉淀为 wiki-style 持久知识，并与 skill 共同演化。对做 long-horizon agent 的团队，应评估：(1) 现有 agent 的执行经验是否被结构化沉淀（而非仅落在日志/轨迹里）；(2) skill library 与知识结构是否能双向检索与共同演化；(3) 是否能用 wiki 形式组织'为什么这么做、下次怎么做'，避免知识与技能脱节。

### 推理时成本治理的启发
CritICL 利用小模型结构化失败模式在推理时通过 ICL 桥接大模型，把弱模型从'答案提供者'变成'失败模式判别器'，避开重复采样与外验证成本。对所有做 LLM 推理时扩展的团队，应评估：(1) 内部任务上是否存在'小模型失败模式结构化 + 大模型修正'的 ICL 桥接机会；(2) 与 self-consistency / verifier-based 方法的成本-质量取舍；(3) 是否能在不增加采样/外验证成本的前提下提升推理质量。

### 企业 agent 合规架构的启发
PES 把 persona 与 execution 分到不同 trust domain、用 governed contract bridge 桥接，persona 可漂移但 execution 必须可审计。对所有做企业 agent 部署的团队，应评估：(1) 现有 agent 架构是否做了 persona/execution 分离；(2) bridge 是否能强制 status summaries 回流但工作证据不可被 persona 篡改；(3) 审计与演化的张力是否被显式建模（而非默认信任合一）。

### 训练范式演进的启发
TTPO 把 RL/OPSD 的 ground truth 依赖换成'利用多数/少数 rollout 不对称性'的 test-time 训练。对做 agentic RL / RLHF / 自演化的团队，应评估：(1) 内部 RL/RLHF 任务上是否能用 rollout 不对称性替代 ground truth；(2) TTT 与 TTT-with-verifier 的成本-质量取舍；(3) 数学推理外的任务是否适用。

### SWE agent 数据治理的启发
SWE-Prime 把 SWE agent 训练从'采大量轨迹'转向'精选高质量轨迹'。对做 coding-agent / SWE 训练的团队，应评估：(1) 训练数据'量大但脏'的瓶颈是否影响模型行为；(2) '高质量'的具体过滤/打分准则是否可工程化；(3) 是否应先做小规模精选数据消融，再决定是否扩大数据规模。

### 攻击侧与防御侧 skill evolution 的启发
RedEvoAgent 用 experience-driven skill evolution 改造红队 agent 的攻击技能沉淀路径。对做 agent 安全评估 / 红队自动化 / 产品级 agent 防护的团队，应评估：(1) 现有红队/防护体系是否依赖固定攻击/检索；(2) 攻击侧与防御侧是否都能从 skill evolution 中受益；(3) 是否需要建立内部红队 agent 与防御 agent 的 skill 双向沉淀机制。

今日信号确认：AI 工程研究焦点正在从'演示与单一指标'转向'运营化 + 训练范式 + 数据治理'——具体表现为：可结构化沉淀的 agent 经验（WikiSkill）、可成本治理的推理时方法（CritICL）、可合规治理的企业 agent 架构（PES）、可替代 ground truth 的 TTT 训练（TTPO）、可精选治理的 SWE agent 训练（SWE-Prime）、可双向进化的攻击/防御 skill evolution（RedEvoAgent）。与昨日（8-27）的 Recuris/Prompt Structure/FID Hides/SPO++/BrowserForge/LAION-BVD 一脉相承但视角从'agent memory + 评估真实化 + 训练组件工程化 + 数据规模化'扩展到'经验沉淀 + 成本治理 + 合规架构'，意味着 AI 工程正在向'运营化（经验沉淀 + 成本治理 + 合规架构）+ 训练范式（TTT 替代 ground truth + 精选 vs 大量）+ 数据规模化'三方向同时演进。
