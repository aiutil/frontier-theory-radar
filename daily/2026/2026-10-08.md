- **底层问题：** 实际生产里 LLM 应用经常是'一批 related narrow task'（批量分类 / 批量抽取 / 批量 review / 批量模板生成）。问题：是不是必须 per-instance call LLM？还是可以让 LLM agent 在 workload 上自主做 capability → artifact 的 distillation，让 artifact 之后可以 amortised 地用？——'bottling' 是不是把 cost 从 O(instances) 拉到 O(artifact + residual calls)？瓶颈在哪里：artifact 是否能 generalize 到 instance-level variance？time budget 协议是什么？
- **新命题 / 新方法 / 新证据：** 提出 bottling = 'agent 收到整个 unlabeled workload + 固定 time budget，agent 自主决定如何把 capability 蒸馏成 artifact / cache / template / specialized solution，平衡 quality + cost'。证据来自：BOTTLED benchmark（agents 在 unlabeled workload 上做 bottling，按 quality-cost 评分）。
- **研究位置：** 介于 LLM serving cost（per-query cost vs batch cost）、agent capability（general agent vs specialized solution）、prompt caching / template reuse（artifact as prompt / template）、distillation（LLM → small model capability transfer）之间——不重训小模型，而是让 agent 自己在 runtime 做 artifact 生成。属于 'ai-agent × llm-evaluation × inference-serving' 路线，与昨日 / 上周 CLIFT（calibrated self-verification）/ MemPilot（on-demand memory curation）在 'agent 自主做 cost-aware capability deployment' 层面同源，与 aiutil 长期关注的 inference-serving × ai-agent × llm-evaluation 主线在 'agent 自主做 capability → artifact distillation' 层面同源。
