## 2. 先说结论
- **今天最值得看什么：** [On Agentic Manipulation Policies](http://arxiv.org/abs/2611.09892v1)（arXiv 2611.09892，Apple AI/ML Research）——**通用大模型直接指挥机械臂，比在示教上训练的专家策略更可靠**。论文把这一类命名为 **agentic manipulation policies (AMPs)**，核心反直觉点是：**harness 本身不提供任何技能**（README/论文逐字：'The basic harness supplies no grasping, pushing, or placing skills'），**agent 自己发展出策略**——搜索隐藏物体、把物体当工具用、自己校准相机。

## 4. 今日深挖论文

- **一句话本质：** 把「机器人操作」这件事的默认分工倒过来——**不再用示教训练专家策略（VLA / WAM），而是让一个通用大模型直接指挥机械臂**，并且**刻意不给它任何技能**，让它自己发展出策略（搜隐藏物体、把物体当工具、自己校准相机）。
- **底层问题：** 过去五年的主流是「**示教 → 专家策略 → 固定任务**」：用人类遥操作数据训一个专用网络，每个新任务都要重新采数据、重新训。而通用大模型时代出现了一个尴尬：**模型很强，但它不会「动手」**。本文问的是——**如果不给模型任何机器人技能，只给一个薄的接口，它能不能自己把活干了？**
- **挑战了什么旧假设：** 它挑战的是「**机器人操作必须由在示教上训练的专家策略来做**」。论文的证据是反过来的对照：不是「通用模型也能做」，而是「**通用模型做得更稳**」——零样本 85.6% 对 VLA 49.2% / WAM 42.9%，真实世界 104/108，失败率降 20x 与 15x。**而且它挑战的第二个假设更狠：「机器人策略需要技能库」。** README/论文逐字写 'The basic harness supplies no grasping, pushing, or placing skills'——**harness 只提供感知与运动接口，不提供任何「怎么做」的知识。**
- **新假设：** **「能写代码调用接口的通用模型 + 一个薄的确定性 harness」比「专用神经策略」更通用、更鲁棒。** 论文的实现方式本身就是这个假设的证明：AMP1 让模型**写 Python 调用 harness**（RGB-D 图像、标定、融合点云、场景模型、定时末端位姿与夹爪指令），**Python 解释器在整个 episode 内常驻**（模型自己 import、自己定义函数），且模型可以在执行前**预览轨迹**。

- **新能力：** ① **零样本跨三类形态同一个 harness 不改**：单臂 / 双臂 / 移动操作共用 `AMP1`；② **真实世界 104/108**（12 任务、3 台机器人），且**失败率相对强基线降 20x / 15x**；③ **加持久 memory 后 RoboDojo 双臂任务失败率相对零样本再降 4.6x**；④ **涌现行为可被列举**：搜索隐藏物体、移动目标而非移动物体、把物体当工具、舀得太宽而抓不住、推一下以便抓取、纠正标定误差、轻轻放置长物、勾住并旋转物体。

### [Graded convolutional networks: scale invariance without the scale and robustness to unknown blur](http://arxiv.org/abs/2611.09878v1)
- **为什么现在不火也值得保存：** ★ **今日第六价值：一篇纯理论 + 数值实验的论文，它的「尺度不变性」论证有一条我们做数据增强时能直接借的判据。**（arXiv 2611.09878《Graded convolutional networks: scale invariance without the scale and robustness to unknown blur》）★ 核心：把图像的高斯 jet 看成**分次向量空间**（尺度 λ 会把 k 阶导数乘 λ^{-k}），证明**局部 graded 卷积恰好就是齐次微分算子**，且一个局部特征对膨胀不变**当且仅当**它经由「尺度归一化的 jet」或「投影到分级加权球面的 retraction」因子化；**在未知高斯模糊下，retraction 只改变尺度，而尺度归一化的 jet 会获得一个任何径向归一化都消不掉的分级因子**；在零 jet 处，retraction 能区分那些径向归一化与连续分类器都区分不了的图像族；基于 retraction 构建的网络对不变特征是**普适的**。★ 实测口径（作者自述）：MNIST 上**两像素模糊下保持 88.4% 准确率**，对照「同一网络跑在尺度归一化导数上」为 **66.2%**；在 Lindeberg 的高斯导数网络里，retraction 把该模糊下的准确率**从 91.5% 提到 95.1%**。★ **今日实测的工件**：论文 HTML 全文实测写明 'The code, the trained networks and the result files from which every table and figure is generated are deposited on Zenodo'；arXiv comment 实测逐字 '26 pages, 2 figures, 7 tables. Code, trained networks and results: https://doi.org/10.5281/zenodo.23997172'；**该 DOI 经 api.datacite.org 实测 HTTP 200，标题逐字 'Code and results for "Graded convolutional networks: scale invariance without the scale and robustness to unknown blur"'**，出版者 Zenodo、年份 2026 → **记录确实存在**。★ **证据不足项（必须写清楚）**：① **zenodo.org 在本环境 SSL 层不可达**（实测 `<urlopen error [SSL] record layer failure>`，record / api / doi 三条通道一致失败），**所以文件清单、体积与是否含训练好的权重今日无法核验**——只能确认「记录存在且标题对应」，不能确认「能下什么」；② 论文**无 arXiv comment 里的会议接收信息**（实测 comment 仅含页数/图数与 Zenodo 链接）；③ 论文自陈其 MNIST-Scale 复现**故意不遵循该 benchmark 的协议**（缩放因子在 [0.3,1] 均匀、验证集顺序改变、测试集缩放依赖训练规模），**故不可与他人 MNIST-Scale 数字直接比较**；④ 无第三方复现。★ 判断：**长尾保存**——「一个不变性到底是「尺度归一化」还是「球面 retraction」」这个区分，对我们判断数据增强/输入归一化是否真的带来鲁棒性，有一条可借的判据；但本体是理论 CV，不进主线。
- **未来触发条件：** 出现开源实现 / 被高质量论文引用 / 进入 benchmark。

### [On the Reliability of Majority-Vote Pseudo-Labels in Test-Time Reinforcement Learning](http://arxiv.org/abs/2611.09872v1)
- **为什么现在不火也值得保存：** ★ **今日第七价值：一篇「把 TTRL 的误差分解清楚」的论文，它的问题设定对我们设计在线评测有直接参考。**（arXiv 2611.09872《On the Reliability of Majority-Vote Pseudo-Labels in Test-Time Reinforcement Learning》）★ 核心：TTRL 用自生成伪标签把预训练模型适配到无标注目标域，而**伪标签的可靠性一直没被理解清楚**；本文分析 online DPO 下的多数票监督，**把误差分解成「population-majority bias」与「prompt 相关的有限 rollout 波动」**，并指出**前者一般无法在没有外部监督的情况下被识别**——所以转而缓解后者，提出 **PC-Dr.DPO（Prompt-Conditional Distributionally Robust DPO）**：按观测到的投票可靠性**在 prompt 内部做条件化鲁棒重加权**，让**对采样敏感的 prompt 产生的更新更保守**；另引入**基于缓存的机制来减少在线适配中的自监督遗忘**。★ 实测口径（作者自述）：在 **6 个数学与知识密集型推理 benchmark、5 个模型骨干**上，PC-Dr.DPO **在 30 个设定中的 24 个**匹配或超过最强 TTRL 基线。★ **证据不足项（必须写清楚，不补写不存在的事实）**：① **纯论文，实测无代码链接、无官方仓库、无项目页**——arXiv HTML 全文实测扫描出的外链全是模型卡与参考文献（openai.com 的 gpt-5-6、qwen.ai 的 qwen3.7、kimi.com 的 kimi-k3、deepseek 的模型卡、ericmitchell.ai 的 cdpo.pdf 等），**没有一条是本文的实现**；② arXiv comment 实测为空，**无会议接收信息**；③ **24/30 里的另外 6 个设定是输还是平、差距多大，摘要未给**，无法判断整体稳健性；④ 「多数票」的多数票数量与投票模型未在摘要给出，需读正文；⑤ 全部数字为作者自述，无第三方复现。★ 判断：**长尾保存**——「population-majority bias 一般不可识别」这句话本身就是一条值得存下来的评测学边界：**用自生成标签做在线评测时，我们可能在一个不可识别的偏差上做优化**。这对我们的 agent 自评设计是一条必须写进 caveat 的提醒。

## 7. 启发

### 系统设计启发
- **今天最值钱的一条是「记忆应该是文件系统，不是状态」。** AMP1 的 memory 实测是 `./workspace` 里的一堆文件——**它天然可 diff、可回滚、可限容、可共享**；而模型产生的输出是可审计的产物（NOTES.md / helpers.py），不是一个我们读不懂的向量。**我们的 skill 今天只有一段 SKILL.md，等于「有能力但没有记忆」——而 AMP1 告诉我们记忆可以极其朴素。**
- **「不给技能，只给接口」是一个可以被更广泛复用的设计范式。** AMP1 的 harness **拒绝物理上不可达或过快的动作，但把碰撞检查留给模型自己**——这是一个非常干净的边界划分：**挡掉不可能的，不替对方做决策。** 我们设计 agent 工具层时应当照抄这条：**工具层做可行性校验，不做策略判断。**
- **「复现纪律」是可以被机器检查的，不只是态度。** AMP1 实测做到了四件事：基准**钉死 commit**、每次 episode **记录它用的 commit**、**偏离 pin 会告警**、**逐图给出一条命令**。这四条全部可以写成脚本。**→ 我们的日报为什么不能这么写？**
- **文档会腐烂，而且腐烂的成本不在成功率里。** 今天被雷达挡在外的那篇（2611.09802）实测：过时的测试命令让 Claude Sonnet 5.5 **每次多花约 2 次 tool call**，**但任务成功率没变**——所以「只看成功率」的评测**根本看不见这笔成本**。**→ 这是对我们评测方法论最直接的一记提醒。**

### Agent 工程启发
- **不要 prompt，要装备（这条昨天说过，今天给了更硬的版本）。** 昨天是「给 skill 补一层会失败的断言」；今天 AMP1 给的是**再上一层：给 skill 配一个会积累的 workspace**。**描述层（SKILL.md）+ 门禁层（单测）+ 记忆层（workspace）——这三层加起来才是一个完整的 skill。** 我们今天只有第一层。
- **「上下文用文件系统管理，而不是塞进窗口」是一个可以直接借的机制。** AMP1 项目页实测逐字写：图像**只有被模型的代码显示时才进入 context**，**最老的被换成指针、模型可以重新加载**。**→ 这对任何「长会话 + 大图像/大日志」的 agent 都适用：把 context 变成一个可重载的目录，而不是一条越来越长的对话。**
- **Agent 的产物应当能被独立审计。** AMP1 的 episode 记录里存着它用的 commit、模型 key、reasoning effort；`src/amp/doctor.py` 逐项体检环境。**→ 我们交付 agent 产物时，「它当时跑在什么条件下」应当是产物的一部分，而不是事后补的说明。**
- **「先选后做」在机器人上的版本是「先选后碰」。** Grasp-TAGS 实测：把 PPO critic 蒸馏成一个轻量 grasp utility network，**在还没接触物体之前**就排好抓取。**→ 与我们谈过的「先路由再执行」同构：能用便宜的前置选择器解决的，不要放进昂贵的执行循环。**

### 研发流程启发
- **「官方链接存在」与「官方链接里有东西」必须分开核。** 今天实测 GRAC 的官方 GitHub 仓库是**空仓库**（tree API 409 / contents 404 / branches 空数组 / size 0 KB / 创建与推送相差 2 秒）。**→ 核验清单加一条：任何「官方实现」链接，入库前打一次 tree API；空仓库要显式标成「代码未发布」，不能标成「有代码」。**
- **默认分支不一定是 main——今天又中了一次。** 今日实测 `SAI-Lab-NYU/CodeQuant2` 的默认分支是 **`camera-ready`**（按 main 取树会拿到空或过期结果），昨日实测 `ceselder/maem` 是 `master`。**→ 核验脚本应自动读 `default_branch`，不要硬编码。**
- **「第三方基准 + 钉 commit」是外部评测可复现的最低门槛。** AMP1 把 RoboLab / CaP-X / RoboDojo 三个基准各钉一个 commit 并把 `make robolab` / `make capx` / `make robodojo` 做成一条命令。**→ 我们如果要在报告里引用任何外部分数，也必须记下那个 commit。**
- **诚实地标注「我用的是哪台机器」应该成为规范。** 今天实测 QAOA-TCS 那篇**由作者自己写明**其效率分析「受不同计算环境约束」——这条作者自陈的限制，我们原样保留。**→ 我们的评测报告也应该有一节「本次结论的适用环境」。**

### 评测方法启发
- **「只看任务成功率」是一个已经被实测证伪的评测口径。** 2611.09802 实测：过时指令让 Claude Sonnet 5.5 **多花约 2 次 tool call（多三分之一）**，**但成功率不变**——**成本被隐藏了**。**→ 我们的 agent 评测必须同时记录「完成任务的成本」，而不仅是「有没有完成」。**
- **评测要能区分「结果对」和「机制对」。** 今天实测 GRAC 同时报了 CIDEr-D（语言质量）与**器械-动作-目标三元组集合精确匹配准确率**（事实一致）——**两个口径一起报，才不会用一个漂亮指标盖住另一个。**
- **自生成标签上做在线优化，可能落在一个不可识别的偏差上。** 2611.09872 实测：TTRL 多数票监督的误差可分解为 population-majority bias 与有限 rollout 波动，**而前者一般无法在没有外部监督的情况下被识别**。**→ 我们做 agent 自评时必须写进 caveat：我们可能在优化一个我们自己看不见的偏差。**
- **推理模型的评测和普通模型不是一回事。** CodeQuant2 实测：推理模型**前几个解码步的激活波动更大**，只按常规文本做校准会漏掉这段早期状态（因此才有 reasoning-aware calibration）。**→ 这条虽然发生在量化侧，但「推理模型要用推理态的样本来校准」这个道理，在评测侧同样成立——用非推理态样本校准出来的结论，对推理模型不一定成立。**
- **缓存类方法必须同时给三个判据。** CPU-ARC 实测强调 ARC 要**可解释、可持续再训练、对输入扰动鲁棒**。**→ 我们评测任何缓存/记忆机制，都该照这三问：能解释吗、能再训吗、扰动下还稳吗。**

### 平台工程启发
- **上下文与记忆都需要「预算」与「锁」。** AMP1 实测的 `--workspace-max-bytes N`（每个任务 60,000–131,072 字节）、`--shared-workspace`（所有任务共享，上限 256,000 字节）、`--workspace-sha SHA`（版本不匹配就拒绝）——**三个参数恰好对应三件平台工程的事：限额、隔离、一致性。** 我们今天给 skill 加 workspace 时应当一次给全。
- **「运行前体检」是一个可以标准化的小组件。** AMP1 有 `amp doctor`（实测 `src/amp/doctor.py` 20,317 B），昨日核验的 Skillware 有 `doctor`（四列 SCHEMA / DEPS / LOAD / ENVS）。**→ 两个不同团队的独立实现都做了同一件事，这说明「运行前体检」是需求，不是偏好。**
- **默认分支、分支名、目录名这类「默认值」要显式管理。** 今天实测 CodeQuant2 用 `camera-ready` 做默认分支——**这意味着任何按 `main` 取树的自动化在它身上都会静默失败。** 平台侧的教训：**所有外部依赖的读取都要走「先问 default_branch」的路径，不要硬编码。**
- **评测基础设施本身也需要版本与回归。** 这是昨天 Terminal-Bench 2.1 那条结论的延续，今天多了两个样本：AMP1 把三个基准钉死 commit，QAOA-TCS 自陈计算环境不同会限制结论。**→ 我们自己的 harness 应当像产品代码一样被维护。**

### 个人学习启发
- **优先读「可复现纪律做得好的」论文，而不是「主张最新」的论文。** 今天 AMP1 排第一不是因为它主张最新（通用模型控制机器人这个想法本身不新），**而是因为它是唯一一篇把复现条件写成可执行规则的一篇。** 昨天 Skillware 排第一也是同一个理由。**→ 这是连续两天验证出同一条择文标准。**
- **今天最该记住的一条数字是「2 次 tool call」。** 过时指令让模型每次多花约 2 次 tool call。**这提醒我：我给模型写的每一段「说明」，都有可能在某个会话里是错的，而且成本不会被成功率显示出来。**
- **今天的反面样本也值得记：GRAC 的官方仓库是空的。** 它提醒我**「论文说有代码」和「代码在那儿」之间有一段需要我亲自走过的路**——这段路每次都要走，不能省。
