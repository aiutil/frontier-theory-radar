## 7. 启发

### Agent memory 结构分离的启发
Recuris 把 long-horizon agent 的 memory 拆成 Working Memory（管任务进度）+ Experiential Memory（管跨轨迹技能库），并把执行变成结构化失败证据。对做 long-horizon agent 的团队，应评估：(1) 现有 agent memory 是否分层（任务态 vs 技能库）；(2) 执行痕迹是否被结构化记录以便失败定位；(3) 技能调用是否能基于'当前任务需求'而非'全历史'——避免被无关历史干扰。

### Prompt 工程影响是'重分布'而非'减少'的启发
Prompt Structure 用 424 任务 × 2 模型 × 5 prompt 变体实证：结构化/安全导向 prompt 不一定让生成代码更安全，可能只是把弱点从 A 类型重分布到 B 类型。对所有做 coding-agent / LLM 应用的团队，应立刻：(1) 把'prompt 变体对照'纳入评测设计——同一任务在多 prompt 变体下统计弱点分布而非只看总体减少；(2) 不要把'用了安全 prompt'等同于'生成安全代码'；(3) 对每类弱点分别报告指标，避免弱点间相互掩盖。

### 生成模型评估可信度的启发
FID Hides 用具体反例（视觉不可识别但匹配 Inception mean/cov 的图像获 FID 24.7 vs 真实图像 FID 58.6）证明 FID 标量不是 calibrated test。对所有用 FID/KID 选型生成模型的团队，应评估：(1) 是否把 FID 数值当作唯一排序依据；(2) 是否做了 FID 偏差检测（如 FID Hides 提出的方法）；(3) 是否在 FID 之外加了分布级/语义级辅助指标；(4) 选型时是否报告 FID 数值的采样波动而非单点数值。

### RL 后训练偏差修正的启发
SPO++ 指出 SPO 的 trajectory-level 中心化与 actor token-weighted 损失不一致，并用 token-weighted 标准化修复。对做 agentic RL / RLHF 后训练的团队，应评估：(1) 当前 advantage 标准化是否考虑 token 维度（而非只按 trajectory 中心化）；(2) 异步 agentic RL 是否付出了不必要的 group-sampling 算力成本；(3) 在长/可变 tool-use 轨迹上是否出现中心化偏差的迹象。

### Web agent 数据规模化的启发
BrowserForge 用并行浏览器沙箱规模化生成 web agent 训练轨迹，把数据规模从千级推到更大。对做 web agent / 浏览器 agent 的团队，应评估：(1) 现有 web agent 训练数据规模是否构成瓶颈；(2) 并行沙箱是否可作为内部 web agent 数据生成基础设施；(3) 是否需要绕过 HTML/可访问性树 token 成本（直接从渲染像素决策）。

### 大规模视频数据集的启发
LAION-BVD 把视频多模态预训练数据推到 10M 小时量级。对做视频多模态/视频理解/视频 agent 的团队，应评估：(1) 是否需要 10M 小时量级数据；(2) 许可协议是否允许商业使用；(3) 内容过滤策略是否符合团队合规要求；(4) 是否与 LAION 此前图像数据集存在类似的合规/版权风险。

## 10. 最终结论
- **结论：** 轻量试点
- **价值类型：** 即时价值
- **原因：** Recuris: Recursive Experiential-Working Memory for long-horizon agent harness 命中 ai-agent 主线（长程 agent 内存）：据摘要，Recursive Self-Improvement 在长程任务上难，因为增长历史掩盖任务状态、技能调用错位。Recuris 用 Working Memory 跟踪任务进度并从 Experiential Memory 选技能——把执行变成可定位失败的结构化证据。'Working Memory 管当前任务 + Experiential Memory 管跨轨迹技能库 + 执行即结构化证据'与昨日 Prime Agent 的'REPL 当外脑 + Continual Harness 跨会话保留 skills/memory/prompts/subagent'同方向，但更聚焦 memory 结构分离——可作为团队 long-horizon agent 的 memory 抽象候选。证据强度中等：方法命名清晰（Experiential/Working Memory 结构化分工）+ 关键词 agent/memory/benchmark 命中。证据不足：code/benchmark 暂无待核验；摘要截断导致 Experiential Memory 的存储/检索机制、Working Memory 的状态表示、与 Prime Agent REPL 的差异评测缺失；建议跟踪其开源与定量结果，1 周内可在内部 long-horizon agent 上做 memory 抽象对比。
- **最大不确定性：** 全部 10 篇论文的 code/benchmark/Papers with Code/OpenReview 链接均暂无待核验；评分与分析基于 arXiv 摘要自述；Recuris 摘要截断导致 Experiential Memory 存储/检索机制、Working Memory 状态表示、与 Prime Agent REPL 的差异评测缺失；Prompt Structure 摘要截断导致 5 种 prompt 变体具体差异、定量结果（各弱点类型前后比例）、所用弱点分类法缺失；FID Hides 摘要截断导致偏差检测/排名/诊断的具体算法、与 KID/其他指标的关系缺失；SPO++ 摘要截断导致与 GRPO/PPO 的定量对比、适用任务类型、稳定性结果缺失；BrowserForge 摘要截断导致具体沙箱架构、轨迹规模、与已有数据集的定量对比缺失；LAION-BVD 摘要截断导致许可协议、内容过滤策略、与已有视频数据集的定量对比缺失；Bellman Calibration、FedV-KGQA、Cross-Problem VRP 摘要均截断导致各自方法细节与定量结果缺失。
