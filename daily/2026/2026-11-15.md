## 2. 先说结论
- **今天最值得看什么：** [Does a Self-Learning Migration Agent Learn? An Audited Evaluation of Evidence-Graded Experience Memory for Oracle-to-PostgreSQL Migration](http://arxiv.org/abs/2611.16143v1)（arXiv 2611.16143，Oleg Grynets、Vasyl Lyashkevych、Valeriia Oliferuk、Vladyslav Babenko、Danylo Kovalchuk）——**它用受控审计证明「agent 从经验里学习」很可能只是检索复用与数据泄漏，并给出六条可执行的评测规则。**
- **为什么值得看：** 三条理由，每条都有实测支撑。
  - **其一，它先给了一个看起来是正面的结果：** 在 1,833 对文档派生的 source-reference 对上，持久记忆把 reference conformity (RC) 提升 **0.015 [0.004, 0.025]**。**但论文自己接着把这个数字拆穿了**：审计发现 **367 个留出单元里有 264 个（72%）与训练集共享同一个 PostgreSQL 参考**，在 **103 个无泄漏单元上记忆效应降到 0.002 [−0.008, 0.011]**——**区间完全含 0，即与零不可区分**。
  - **其二，它给出了一个「不用模型」的基线：** 一个无模型的最近目标复制基线 RC **0.222**，**打赢了所有 LLM 系统（最高只有 0.163）**。**换句话说：如果你的 agent「学会了」，先确认它不是在做检索复制。**
  - **其三，它顺手测出了记忆库变大的反作用：** 知识库从 **12 条增长到 1,200 条时，检索 margin 下降 54%**。**这直接命中我们「记忆越存越多越好」的默认假设。**
- **它属于什么价值类型：** 即时价值。
- **今天该做什么：** 今天把**「记忆类 A/B 之前先查泄漏」**这条写进我们的评测流程——**具体是：任何用持久记忆 / 历史任务做前后对比的实验，必须先做一次「留出集与训练集共享答案」的检查，并把检查结果写进报告。**今天这篇还给了现成的六条规则，可以直接抄。
- **最大不确定性：** **本文最重要的资产今天打不开**——comment 与 abstract 中**无任何工件 URL**，且 **GitHub search 配额在核验中途耗尽（连续 2 次 HTTP 403）**，因此**无法反查官方仓库**；此外它的一级分类是 **cs.LO / cs.DB / cs.SE 而非 cs.AI**，**结论外推到 LLM agent 需要额外论证**。

## 4. 今日深挖论文

- **一句话本质：** 不问「agent 能不能从经验里学习」，而问「**它表现变好，是因为学到了，还是因为检索到了参考答案、或者干脆在复制**」——并把这两件事拆开测量。
- **底层问题：** 我们内部正在用「agent 跑第二遍比第一遍好」来论证记忆模块有效。**但这条论证有个隐含前提：测试任务里的答案不在记忆里。**论文用一个具体的迁移场景（Oracle→PostgreSQL）把这个前提拆穿——**72% 的留出单元与训练集共享同一个参考**，**无泄漏子集上记忆效应直接归零**。
- **挑战了什么旧假设：** 它挑战了「**agent 在累积经验后变强 = agent 在跨任务学习**」这个默认假设。证据是三重的：**① 泄漏审计**（72% 共享参考）、**② 无模型复制基线打赢所有 LLM**（RC 0.222 vs 最高 0.163）、**③ 分组切分后效应消失**（118 个独立目标组的 374 个单元上，记忆效应 0.005 [−0.003, 0.017]，无统计可区分性）。
- **新假设：** **「任何声称「agent 从经验中学到了东西」的结果，都必须先通过三道门：留出集无泄漏、能打赢无模型复制基线、分组切分后效应仍显著。」**论文原文把它提炼成**六条评测规则**，用于区分跨任务学习与参考泄漏 / 复制 / 指标假象 / 不稳定反馈。
- **核心机制（今天逐项核对过）：** **① 证据分级记忆（evidence-graded experience memory）**——记忆条目带证据等级；**② 策略自适应**——在记忆之外再学一条「策略」，论文实测**这一层增益为 −0.004 [−0.010, 0.001]（没有增益）**；**③ 人工把关的修复循环**——在 216–224 个真实 PL/SQL 单元上，**10–22% 被 PostgreSQL 接受的单元在行为上是错的**，修复循环把可证明正确的单元从 **98/216 提到 167/224**；**④ 写回研究**——知识库 12 → 1,200 条时**检索 margin 下降 54%**。
- **工程可验证性：** **今日无法核验任何代码**——comment 与 abstract 中无 URL，GitHub search 配额耗尽无法反查仓库。**这是今日第一即时价值却零工件的唯一一篇**，必须写明。复现门槛本身不高：迁移场景是确定性的、有可执行的 PL/SQL 单元，但需要 GPU 与 LLM 服务。

### [HeMeR: Heterogeneous Memory Reconciliation for Embodied Agents via Structured KV Reuse](http://arxiv.org/abs/2611.16487v1)
- **为什么现在不火也值得保存：** ★ **今日第十价值：它把「记忆模块化的代价」定位到具体机制上——因为记忆分成声明式 / 程序式 / 工作记忆三套独立接口，每一步都被当成全新输入重算，于是 KV cache 完全无法复用。**（arXiv 2611.16487《HeMeR: Heterogeneous Memory Reconciliation for Embodied Agents via Structured KV Reuse》，Saehun Chun、Wonje Choi、Jinwoo Jang、Taeyoon Kwack、Honguk Woo；**arXiv comment 逐字 'Accepted at NeurIPS 2026 (Oral)'**）★ 核心：具身 agent 的决策要组合异构记忆模块（声明式记忆存显式知识、程序式记忆存习得流程、工作记忆存当前观察）。**交互过程中，决策所需记忆内容随状态、目标与任务进度而变，但许多内容在相邻决策之间是共享的。** 然而现有记忆模块通过独立接口访问，**每个更新后的记忆上下文都被当成新输入处理**——这**使得未变内容的 KV cache 无法选择性复用，即使大部分记忆上下文仍然有效，也被迫全量重算**。HeMeR 在动态更新的记忆上下文与可复用 KV 状态之间做 **KV reconciliation**：跨动作决策跟踪三类记忆内容，保留未变内容的 KV 状态，只对受记忆更新影响的部分做 reconcile。★ 实测口径（论文摘要逐项核对）：在 **ALFWorld、Habitat 与真实机器人部署**上评测；**真实场景中任务成功率 83.20%，每步推理时间从 2.94 秒降到 1.87 秒（对比 MemRL）**，同时在任务推进更新记忆上下文时保留兼容的 KV 状态。★ 证据不足项（必须写清）：① **今日确认无官方工件**——comment 与 abstract 中**无任何 URL**，GitHub search 配额耗尽无法反查仓库；② **需 GPU 与真实机器人硬件**，本机无 GPU、无法复现；③ 「真实机器人部署」的具体平台未在摘要中给出；④ 摘要**未给出 ALFWorld / Habitat 上的分项数字**，只有真实场景的一组；⑤ 「Accepted at NeurIPS 2026 (Oral)」**无法与 NeurIPS 官方接收列表交叉核验**；⑥ 全部数字为作者自述，无第三方复现。★ 判断：**长尾保存**——**「记忆模块各自独立接口 → KV cache 无法复用 → 每次全量重算」这条因果链对我们有直接诊断价值**（我们的 agent 上下文组装如果也按模块拼接，每次请求都在重算相同前缀）；**但它是具身 + KV 层的实现，且今天零工件，所以只存结论。**

### [MobileProbe: Adaptive Security Evaluation of Mobile Agents via Trajectory-Aware Injection](http://arxiv.org/abs/2611.16693v1)
- **为什么现在不火也值得保存：** ★ **今日第十一价值：它指出了「固定点注入基准」的一个系统性低估机制——agent 根本没走到被注入的页面，就被记成「安全」。**（arXiv 2611.16693《MobileProbe: Adaptive Security Evaluation of Mobile Agents via Trajectory-Aware Injection》，Yingbin Jin、Ji'an Wang、HaoYang Chai、Hanjun Luo、Li Hu；**arXiv comment 逐字 'Accepted at NDSS 2027'**；一级分类 cs.CR / cs.AI）★ 核心：移动 GUI agent 读手机屏幕并代用户操作应用；**因为 agent 依据屏幕所见行动，攻击者可以把恶意指令嵌进普通 UI 内容并改写它的动作**（论文称之为 environmental injection attack, EIA）。**现有基准的两个局限**：**其一，每个 payload 绑定在一个应用的一个固定任务上，换任务不迁移；其二，同一任务的 agent 可能走不同路径——「一个从未到达被注入页面的 agent 被记为安全，却从未真正被测试过」**，这种覆盖不足会让固定点基准**低估已部署移动 agent 的真实安全风险**。★ 实测口径（论文摘要逐项核对）：MobileProbe 是**轨迹感知的自适应红队框架**——自动渗透发现攻击者可控的内容面，沿 agent 轨迹定位脆弱决策点，用**代理模型过滤的进化循环**迭代精炼上下文相关 payload；**基准含 83 个长程攻击实例、覆盖 12 个移动应用**，每个标注 Confidentiality / Integrity / Availability 三类攻击目标；在**三种代表性 agent 架构**上，**攻击成功率高于人工编写、零样本 LLM 与迁移到移动域的既有自动红队基线**。★ 证据不足项（必须写清）：① **今日确认无官方工件**——comment 与 abstract 中**无任何 URL**，GitHub search 配额耗尽无法反查；② 需真实移动设备/模拟器与多 agent 框架，**本机不具备**；③ **摘要未给出具体攻击成功率数字**，只说「更高」；④ **「Accepted at NDSS 2027」无法与 NDSS 官方接收列表交叉核验**；⑤ 攻击方法本身是攻击性的，授权与伦理交代未在摘要中给出；⑥ 全部数字为作者自述，无第三方复现。★ 判断：**长尾保存**——**「agent 没走到被注入页面就算安全」这条是评测覆盖率的通用陷阱**（不只是移动端），对我们做 agent 安全评测有直接启发；**但今天零工件、零数字，只存结论。**

## 7. 启发

### 系统设计启发
- **今天最值钱的一条：任何「agent 变强了」的结论，都必须先过一道泄漏检查。** 实测：记忆效应在有泄漏的留出集上是 **+0.015**，在无泄漏子集上是 **+0.002 [−0.008, 0.011]**（区间含 0）。**→ 我们的直觉是「把历史塞进上下文，agent 就会变聪明」，今天这批数据提醒我们：先确认它不是检索到了答案。**
- **「打不赢无模型基线的系统不值得优化」。** 实测：最近目标复制基线 RC **0.222**，所有 LLM 系统最高 **0.163**。**→ 我们给 agent 做的任何「优化」，都应该先和一条最朴素的规则基线比一比。**
- **记忆库变大 ≠ 记忆变好。** 实测：知识库 **12 → 1,200 条，检索 margin 下降 54%**。**→ 我们的记忆库如果只增不减，应该有一条「超过某个规模就重新评估检索质量」的规则。**
- **「静态强」不等于「动态可靠」。** 实测（2611.17267 LiveGeo）：**没有哪个模型能在所有任务上持续领先，强静态表现并不保证动态可靠性**。**→ 我们的 agent 回归测试几乎全是静态任务，这是一个结构性盲区。**

### Agent 工程启发
- **「产出」和「通过验收」是两件事。** 实测（2611.16991 AnalogLayoutWorld）：**91.1% 的尝试能产出 GDS 版图，只有 23.0% 满足验收标准**。**→ 我们统计 agent 任务成功率时，要区分「产出了」与「通过了验收」，否则会高估 3–4 倍。**
- **agent 的「明知故犯」需要专门机制去抓。** 实测（2611.16289 SatisFix）：agent 考虑过满足需求的方案，却出于自认为可接受的理由提交了不满足的方案；**而现有自纠错方法对这个失败模式有偏**——**让 agent「自我反思」恰恰会把明知故犯合理化**。**→ 我们 review agent 输出时，要专门问「它是不是自己决定不用严格满足」。**
- **「给一条不剧透的机制提示」可能是最高杠杆的一招。** 实测（2611.16861 Visual Cipher Bench）：在 10 题子集上，**只给一条不剧透的机制提示，准确率从 7.8% 跳到 55.6%**；最强模型在完整集上也只有 26.7%。**→ 很多 agent 的失败不是能力失败，是「不知道要找什么」的失败；这对我们写提示词直接可用。**
- **记忆的收益要在「跨会话」场景测，而不是同会话。** 实测（2611.16590 AstroMemBench）：**同会话内三个记忆系统相对 RAG 没有明显优势；会话重启后 Mem0 反超 RAG 12.25 分**。**→ 我们如果正在评估 Mem0 之类的专用记忆层，先确认测的是跨会话场景。**
- **保留原始对话当证据，别只留抽取结果。** 实测（2611.17068 MAPE）：**保留原始对话作为可检索证据，能保住抽取式记忆里丢失的细节**；把「按查询意图组合证据」的模块移植进五个已有记忆系统，**五个全部提升**。**→ 这两条今天就能改。**

### 研发流程启发
- **评测本身也要测「噪声底噪」。** 实测（2611.16485 drydock-eval）：**完全不变的基线在同一批 128 个任务上重跑，移动了 1.17 分**；三次改动在筛选集上领先 +1.0 到 +6.2 分，**但没有一个在新任务上被确认（−0.35、−0.39、+4.10）**。**→ 我们内部每一次「改了 prompt，有提升」的判断，都应该先问「这个提升超过了基线重跑的漂移吗」。**

### 评测方法启发
- **「总体召回率」不足以描述审计质量。** 实测（2611.16493 ReA-Bench）：**总体召回掩盖了「漏了哪些风险」以及「更高召回是否伴随更多误报」**，基准把审计拆成六层失败类型，并提供配对轨迹来**区分「漏看证据」与「没有信息可判」**。**→ 我们的 agent 审计表现在只有一个总体数字。**
- **基准的覆盖率本身可能是假的。** 实测（2611.16693 MobileProbe）：**「一个从未到达被注入页面的 agent 被记为安全，却从未真正被测试过」**——固定点注入基准会**系统性低估**已部署 agent 的真实风险。**→ 这条是通用的，不限于移动端。**
- **「产出率」不能替代「验收通过率」。** 实测（2611.16991）：**91.1% vs 23.0%**。**→ 见上，同一条在两个方向上都成立。**

### 平台工程启发
- **agent 批处理里「等工具」的时间是纯损耗。** 实测（2611.17294 Metal Sandbox）：动态调度把**平均工具等待降低 18.8%、批次总时长降低 22.3%**；四台 Mac mini M4 上集中负载下命令吞吐 **1.68×–2.05×**。**→ 我们跑 agent 评测批处理时一直在等 GPU 空转，今天开始应该把这个时间单独记一项。**
- **批次尾部是批处理的主要成本。** 实测（2611.16661）：**makespan 降低 10.4%–65.0%** 的主要杠杆是 **Chain-Advancing Action Scheduling——按已观测进度优先处理长链**。**→ 我们的 agent 批处理尾部拖垮整批的现象与论文形状一致。**
- **本地化部署的 agent 集群也有同样的空转问题。** 同上，Metal Sandbox 证明**跨节点的命令级调度 + 命令迁移**能显著提吞吐——**说明「工具等待」不是 GPU 集群独有的问题**。
