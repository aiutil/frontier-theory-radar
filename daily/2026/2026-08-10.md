## 4. 今日深挖论文

- **一句话本质：** 构建 tool-use agent 的下一个关键选型不是'用哪个模型'，而是'怎么让 agent 调工具'——程序化工具调用（写脚本链式/并行）vs 原生 JSON 工具调用的系统性跨代际实证对比，可能改变 agent 工具调用的默认实践；而可信的 agent 评估需要 anytime-valid stopping 来在证据足够时立即停止，而不是烧满固定预算。
- **底层问题：** 随着代码能力模型（code-capable models）的成熟，工具调用有了两条路径：一是传统的原生 JSON 函数调用（逐个调用、刚性），二是程序化工具调用（写脚本自然链式/并行）。此前缺乏在既有 benchmark 上跨当前与先前模型代际、在真实世界任务条件下的系统性对比。同时，agent 对战评估面临'该打多少局'的不确定性——固定预算要么浪费要么过早停止，而朴素 optional stopping 会使置信水平失效。

## 7. 启发

### Agent 工具调用选型的启发
The Bitter Lesson of Tool Calling 揭示：随着代码能力模型成熟，tool-use agent 的工具调用范式选择（程序化脚本调用 vs 原生 JSON 调用）可能成为比 backbone 选型更根本的工程决策。程序化调用让工具能自然链式/并行，可能对完成率/延迟/成本有跨代际稳定影响。对构建 tool-use agent 的团队，应把'PTC vs JSON'纳入 agent 工具调用选型的默认 checklist。

### Agent 评估降本的启发
AV-AIVAT 提醒：agent 对战评估的降本关键不是减固定预算，而是 anytime-valid 自适应停止——在证据足够时立即停，置信水平不打折。'74x cheaper'说明现有固定预算评估存在巨大浪费。'anytime-valid 置信区间 + 自适应停止'是 agent 评估流水线的长期优化方向。

### Agent 上下文信任的启发
MIST 把上下文信任重新定义为 selective trust：agent 既要能抵抗误导信号（不盲信），又要在上下文正确时利用它（不盲拒）。'何时该信外部上下文、何时不该信'是构建可靠 RAG/agent 的核心张力，值得有专属评测维度。

### Agent 训练数据合成的启发
CalibForge 指出：agent 训练任务的难度标定可以从人工转为自动化——用对抗性 solver 校准和多 solver 分歧检测，自动合成难度合适、可验证的 terminal agent 训练任务。'对抗性校准 + multi-solver 分歧'是 agent 训练数据合成流水线的可迁移思路。

### Agent 治理的启发
Resourced Authority 提出：已部署 agent 的治理可以从'规则约束'转为'资源杠杆'——通过计算预算让授权自我执行（self-enforcing），使 agent 在耗尽预算前必须重新获得授权。这是 agent 治理的机制设计层面创新。

### 对未来 6-12 个月技术趋势的启发
三天连续观察确认趋势焦点沿三条线推进：agent 工具调用侧从'能调工具'向'高效调工具（PTC vs JSON 范式选型）'演进；agent 评估侧从'固定预算'向'anytime-valid 自适应停止'演进；agent 数据侧从'人工标注任务'向'对抗性 solver 自动合成与校准'演进。三者共同指向'把 agent 的工具调用效率、评估成本与训练数据质量下沉到方法层'。
