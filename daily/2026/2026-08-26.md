## 7. 启发

### Agent harness 形态升级的启发
Prime Agent 把持久化 REPL 当作 agent 的'外脑'——以可执行代码而非线性 prompt 处理 context，并把 history/memory/skills/prompts/subagent 规格跨会话保留。这标志着 agent 从'单次 prompt 工作流'走向'跨会话可积累能力的 harness'。对部署长程 agent 的团队，应评估：(1) 团队现有 agent harness 是否支持程序化 context 处理（REPL 形式）；(2) 是否能把 skills / subagent 规格沉淀为可复用的资产——而非每次会话从零开始；(3) 是否能把 memory 跨会话保留而非仅 session 内累积。

### Coding-agent 评测盲区的启发
SWE Refactor Bench 命名 Blindness：现有 coding-agent 基准只验证'行为正确性'，不验证'migration 是否真的发生'——agent 可以直接复制原实现来通过测试。对所有做 coding-agent 评测的团队，应立刻把'迁移真实性检测'纳入评测设计：(1) 对迁移任务加'迁移前/后 diff 检测'，确保改动真发生；(2) 对所有'目标只是过测试'的任务加'行为与改动一致性检测'；(3) 区分'行为正确'与'过程正确'两个评测维度。

### Critic 训练稳定性的启发
BPCO 系统化稳定 critic 训练（DPPO + bounded value + MC value target + unnormalized advantage），把'可靠 critic'从 GRPO 的替代品变成可工程化组件。对做 RLHF / RLAIF 后训练工程或希望降低 group-sampling 算力成本的团队，应评估：(1) 当前后训练是否依赖 GRPO 这类 group-based 方法，是否付出了高 group-sampling 算力成本；(2) BPCO recipe 组件（DPPO / bounded value / MC target / unnormalized advantage）是否可借鉴到团队 RL pipeline；(3) 在内部任务上做小规模消融，验证 critic 路线是否真能稳定训练。

### World model 结构分离的启发
ReWorld 用 per-head 混合 attention window 分离 control 与 memory（大部分 head 短期，少量 global head 全历史）+ random head routing 避免能力绑定固定 head。这示范了'结构性矛盾问题'的一种通用解法：用结构分工而非参数共享解决不同子任务的能力冲突。对做长程 agent / 长上下文模型 / 多任务模型的团队，应评估：当前模型是否存在'短程 X 与长程 Y'的能力冲突，能否借鉴 per-head / per-layer 的分工策略。

### 训练时污染作为鲁棒性维度的启发
ICS 鲁棒性工作把'训练时污染'作为 ML 鲁棒性维度（11 种 pipeline × SWaT）。对所有做 ML 模型上线 / 数据治理的团队，应评估：当前模型鲁棒性评估是否覆盖'训练数据被污染'这一场景（日志篡改、标签错误、不安全再训练）——这是上线 ML 系统常被忽略的失效面。

### 对未来 6-12 个月技术趋势的启发
今日信号确认：agent 走向部署的研究焦点正在从'更强的单次推理/演示'转向'agent harness 形态 + 评测基础设施 + 训练稳定性基础设施'——具体表现为：跨会话可积累能力的 harness（Prime Agent）、可检测评测盲区的基准（SWE Refactor Bench）、可工程化的 critic 训练 recipe（BPCO）、可分离结构矛盾的 world model 架构（ReWorld）、可收敛到合法 token embedding 的连续 LM（ConvergeFlow）。这与昨日（8-25）的 agent 评测/知识基础设施信号一脉相承，但视角从'外部评测'扩展到'内部 harness 与训练稳定性'，意味着 agent 工程正在向'长程化 + 真实化 + 稳定化'三方向同时演进。
