## 4. 今日深挖论文

- **一句话本质：** HoS 证明 prompt injection 防御**不一定要动模型的权重**——可以只在注意力上加 18K 个参数，让模型自己学会「哪些 token 可以听」。
- **底层问题：** 传统防线要么改模型（SecAlign++ 微调，要么全参要么部分）、要么改架构（ASIDE 在输入侧加通道）。前者贵且伤效用，后者要重训且作者观察到它在 tool use 上几乎不可用（AgentDojo 仅 10% 效用）。HoS 问的是：**如果威胁模型是「不可信内容混进了上下文」，那最小的干预点在哪？**答案是注意力分配本身——一个可信 token 与一个不可信 token 之间的差别，模型本来就能从内容里看出来，只是没有被训练去利用这个差别。于是 HoS 让每个注意力头学一个门：这个头在面对可信 query 时该看多少不可信 key。
- **新命题 / 新方法 / 新证据：** 方法上：per-head 的**可学习注意力门**，配合三通道标注（trusted / untrusted / chat template），门以极小学习率在 DPO 式流程上训练。证据上，作者给了一个很硬的对照——**同一个黑盒 RL-Hammer 攻击，在 GPT-OSS-20B 上 97%、在 SecAlign 上 85%、在 HoS 上 10%**；以及一个白盒对照——**Claudini 需要 3 倍 FLOPs 才能对 HoS 打到与打基座相同的 ASR**。更关键的是作者做了**机制分析**：用因果头消融与角色混淆探针去看门到底学到了什么，发现多数头把注意力从不可信内容移开，而少数头**移向**不可信内容并支持注入检测——这解释了为什么『压低注意力』不是全部机制，也解释了作者为什么强调**均匀抑制**（用一个共享的未训练 logit 压低所有不可信 key）达不到同样的安全–效用权衡（附录 C）。这一点对我们尤其重要：**这说明防御不是一条阈值，而是一个需要按头学出来的分布。**
- **研究位置：** 源头论文（方法侧）。它把三个社群的既有结论接了起来：SecAlign++ 代表『微调路线』，ASIDE 代表『架构路线』，HoS 代表『注意力门路线』，并且用同一套 benchmark 三路对照。与前几天记录的 I-HITL（2610.35835）属同族但方向相反：I-HITL 问『审批通道能不能不被 agent 读到』，HoS 问『就算不可信内容进来了，模型能不能不被它指挥』——**一个防入口，一个防影响，可以叠加**。
- **工程可验证性：** 有明确代码入口，可安排最小实验。仓库结构今日已核对：src/heads_of_security/、demos/、gates/、tests/、configs/；gates/ 下按模型与学习率分目录存放 safetensors；pyproject 提供 vLLM 插件入口（vllm.general_plugins → heads_of_security.vllm_gates:register），README 给出 load_gated_model 与 load_gated_model_local 两种加载方式。⚠️ 边界：仓库 tests/ 共 270 项需要 CUDA 基座模型，今日本地仅确认前 61 项通过，**全量结果待核验/暂无**；huggingface.co 本机直连超时，因此 imperial-cpg/hos-gpt-oss-20b 等托管模型 ID 是否可下载**待核验/暂无**（但仓库内 gates/ 已含权重，可用本地路径绕开）。
- **趋势关联：** 值得纳入趋势雷达继续观察。它把『prompt injection 防御』从『大模型安全工程』推向『注意力级的轻量干预』，与近期『不改权重、用少量可学习参数改造行为』的一族方向同向。观察问题：① 是否出现更多架构（MoE、扩散语言模型）上的移植；② 是否有第三方把它接进主流推理框架而不只是 vLLM；③ 是否有跟进工作把门与因果解释（本文的机制分析）结合成可解释的防御。
- **长尾价值：** 即使今天不接入，它的**方法论比机制更耐用**：『当威胁是「不可信内容混入上下文」时，最小干预点可能在注意力分配，而不是权重』。这条在 RAG、agent 读网页、agent 读邮件、agent 读 MCP 返回值等我们全部场景里都成立，并且它可以迁移成一条**架构选型规则**：优先考虑能标注『可信/不可信』并让模型在注意力层区分二者的方案，而不是优先考虑再训一遍模型。
- **启发：** 今天的第二个即时价值 GEPA-Curator（2610.37651）恰好是它的镜像：HoS 说『防御要轻、要精准落在正确的位置』，GEPA-Curator 说『学习要准，别把噪声当信号』。两篇合起来给出一条统一的方法论——**在系统里区分『信号』与『噪声』，并且只在正确的位置做最小干预**。HoS 在注意力上区分可信与不可信，GEPA-Curator 在失败日志里区分 prompt 归因成立与不成立的失败。第三篇 EnvSched（2610.37609）补上第三块：**连采样哪些任务都要区分信息量与冗余**。今日三篇即时价值恰好构成一条完整链条。

### [Attention as Lattice Gauge Theory: Relations Interact Only Through Wilson Loops](http://arxiv.org/abs/2610.37656v1)
- **为什么现在不火也值得保存：** 今日长尾价值第三。据 arXiv 2610.37656 摘要与 LaTeXML HTML 全文（今日回原文逐字复核，24.7KB 正文可读，arXiv comments 标注『7 pages, 1 figure. ## 7. 启发

### 系统设计启发
- **防御的落点可以不是权重。** HoS 证明『可信 / 不可信 token 的注意力分配』是一个可学习、可插拔、18K 参数的干预点。面对『不可信内容混入上下文』这类威胁，架构选型时应优先问『有没有更小的干预点』，而不是默认『再训一遍』。
- **信任通道应该是一等标注。** HoS 把 token 标成 trusted / untrusted / template 三类；我们做 RAG、agent 读工具返回值、读邮件、读网页时，**来源可信度应当是被显式标注并传给模型的一等数据，而不是靠 prompt 里写一句『以下内容不可信』**。

### Agent 工程启发
- **注意力门不改变模型能做什么，只改变它听谁的。** 这条形态与我们的 agent 形态高度契合：我们的 agent 本来就要读不可信内容（工具返回、网页、邮件），但不该听它们的指令。
- **『均匀压制』不等于『学会区分』。** 作者的附录 C 表明，用一个共享的未训练 logit 压低所有不可信 token 的注意力，虽然也能降 ASR，但会同时大幅降低任务完成率——**防御需要按头学出分布，不是一条全局阈值**。任何我们自己做『抑制某类输入影响』的设计，都要先做这个对照。
- **失败不等于 prompt 的错。** GEPA-Curator 指出 agent 的失败可能来自 harness、执行随机性、judge 噪声或任务本身不可行；把这些喂给反思式优化器会让它**把噪声误归因为 prompt 缺陷**。我们今天就在做反射式优化，所以这条要立刻生效。

### 研发流程启发
- **证据分级要在报告里写成制度。** 今日 HoS 的价值之所以能排第一，是因为我们能明确区分四级：作者自述数值 / 官方代码存在 / 已训练权重可读 / 本地实跑通过。报告里每条结论都标了级别，这比给一个笼统的高分有用得多。
- **仓库里没有被论文正文强调的东西，往往更值得抄。** 今日 EnvSched 论文正文没细讲，但它代码里的 id_hack_guard 规定『怀疑不够，必须同时满足组内优势为正 + 原始奖励重放一致 + 单条反事实上确有收益三条』——这个三条件门槛比论文的一句话更能直接用。

### 评测方法启发
- **对照组要按预算分档报告。** Hexels 论文把对比分成内存匹配 / 图元匹配 / 无约束三档，让『省了多少』与『好了多少』可以分别归因。我们只报一种设定的对比时，经常说不清改进来自哪里。
- **『危险但成功』要单独计数。** 机器人那篇把『不掉落』当一等指标测量；我们的 agent 评测里，『成功但越权』和『失败但安全』现在混在同一个成功率里。
- **按失败类型分桶，不只报总体成功率。** 长期记忆那篇与前几天记录的临床那篇都指向同一件事：**『做错了』与『该做没做』必须分开计数**，而且要先判断瓶颈在记忆之前还是之后——LongChang 指出完整 transcript 的准确率可能低于完全不做笔记，即证据在压缩之前就丢了。

### 平台工程启发
- **候选策略要在同一批输入上并行比较。** PORTAL 的核心是让所有候选预测在同一个输入上被同时评估，一份标签就能比较全部候选；并显式定义停止条件（当剩余标签不可能改变选择时停止查询）。我们的 agent 每次只跑一个配置，是在为并行对比支付 N 倍成本。
- **『它到底发生了吗』需要独立确认路径。** 跨链那篇记录了一个非预期发现：一条费用错误的消息会被路由出去然后**静默地永远不执行**。跨服务、跨模型、跨云的调用同理——必须有一条独立于调用本身的确认路径。

### 个人学习启发
- **优先读能改变我们决策规则的论文，而不只是读热门方向。** 今日三篇即时价值里，只有 HoS 涉及模型本身，但另外两篇（GEPA-Curator、EnvSched）直接改变我们的流程；而三篇 robotics / 3D / 化学论文虽冷门，各自也留了一条今天就能用的判断。**冷门不等于无价值，价值在于能否改写我们的清单。**

## 10. 最终结论
- **结论：** 重点学习
- **价值类型：** 即时价值
