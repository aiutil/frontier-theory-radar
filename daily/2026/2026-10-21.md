## 4. 今日深挖论文

- **一句话本质：** OpenVLHarness（[2610.26860](http://arxiv.org/abs/2610.26860)）把多模态 agent 答不好的原因定位到缺少外部证据而不是推理预算不足，并把修复做成三层可复用的 harness，而不是一个新模型。
- **底层问题：** 很多视觉推理任务需要 'grounded perception, external knowledge, and numerical measurements obtained through heterogeneous tools'，这些证据既进不来也留不住——作者用 22 个 benchmark 的受控实验说明单纯加大推理预算只有 'modest gains'。
- **新命题 / 新方法 / 新证据：** 三个机制各解决一个具体缺口：(1) capability layer 把异构后端统一成任务级工具接口，并把返回结果 'converting their outputs into model-readable observations'；(2) persistent multimodal memory 'retains the corresponding images, structured data, and web references as addressable artifacts throughout each query'，而不是让证据留在上下文里被冲掉；(3) coding interface 'executes generated programs over stored data'，使 'computations that combine results from multiple tools' 成为可能。三者合起来支撑 'an iterative process of acquiring, inspecting, and composing multimodal evidence'。
- **研究位置：** 属于 harness / 工具编排层的改进论文，不是新模型也不是新训练方法；与昨日同源的「agent 从会调工具走向会获取-检查-组合证据」主线一致，属于该主线的结构化实现。
- **工程可验证性：** 证据维度足够（22 benchmark × 8 backbone，含闭源 GPT-6 系列与 Codex、Visual Sketchpad 对照），但摘要未给出代码或 benchmark 链接，工程可验证性暂无可核验入口——需打开 PDF 确认 harness 与工具适配协议是否开源。
- **趋势关联：** 与 WeAct（能力组合）、Agima（执行前想象）构成今日「agent 执行前的证据与能力治理」三件套；与 AnyGoal（world model 在目标重组下失效）互为选型约束。
- **长尾价值：** 即便三件套明天被超越，「证据以可寻址 artifact 形式跨步骤保留」与「工具输出一律转成模型可读观测」这两条 harness 规则本身可长期复用。
- **启发：** 当 agent 在某类任务上怎么加推理预算都不涨时，先怀疑证据管道（工具能否输出、输出是否留得住、多工具结果能否被组合计算），而不是先换模型。
- **行动建议：** 今天完成三件事——(1) 写 visual-tool-harness checklist（三层结构 + 每层的失败模式）；(2) 评估给现有 agent 增加能力切换工具的可行性（WeAct 路线不需改 serving 协议）；(3) 读 Agima 仓库（https://github.com/Agentic-Imagination/Agima ，今日实测可达）确认 omni 训练成本量级，判断「先想象后执行」能否进入我们的最小实验。

## 7. 启发

### Agent 工程启发：证据管道优先于推理预算
- OpenVLHarness（[2610.26860](http://arxiv.org/abs/2610.26860)）最有迁移价值的一条不是分数，而是它先证伪了 '加推理预算' 再改结构。遇到 agent 能力瓶颈时，这个诊断顺序值得固化成 checklist 第一问：证据拿不到、留不住、还是算不动？
- 三层 harness 各自对应一类常见缺陷：capability layer 对应 '工具能调但输出模型读不懂'，persistent memory 对应 '证据在多步中被冲掉'，coding interface 对应 '多工具结果无法组合计算'。

### 能力组合启发：把能力路由做成动作而不是配置
- WeAct（[2610.26847](http://arxiv.org/abs/2610.26847)）的关键工程性质是走 'the model's native tool-calling interface'，因此不需要额外 head、不需要改 serving 协议。它对比的 'static adapter merging maintain a fixed parameter configuration throughout execution' 正好描述了我们当前长程 agent 的现状——全程一套权重。
- 它报告的 '27.5% relative' 增益来自 'the strongest static LoRA-merging method' 这一强基线，说明静态合并的天花板是真实存在的限制，而非仅是实现不便。

### 执行前想象的启发：稀疏反馈场景收益最大
- Agima（[2610.26845](http://arxiv.org/abs/2610.26845)）给出 'SFT alone on two-box Sokoban → 四箱任务 40% vs 纯动作规划器 2%'，且 'seeing the real board only once every five moves'。适用边界很清楚：反馈稀疏且动作不可逆的场景（工具调用有副作用、批量数据操作、下发不可撤回的配置）才值得付这份成本。
- 更有价值的是它对行为的观察：'learns to conduct forward thinking only when necessary, and branches more frequently at critical decision points'——先想象的成本要能被学习出来，而不是每步都付。

### 选型约束启发：分布内分数会骗人
- AnyGoal（[2610.26844](http://arxiv.org/abs/2610.26844)）的负面结论 'current models consistently exhibit failures under these recombinations'，加上它对 benchmark 的克制设计（单因子仍在训练支撑内、只是组合被低估），说明 world-model 选型必须带 goal-shift 变体。只测训练分布内任务等于没测。
- PhysRSI（[2610.26848](http://arxiv.org/abs/2610.26848)）补了第二刀：五轴指标 'distinguish systems with close public benchmark averages'，且 'high scores need not come with early or efficient gains'。总分高不等于在学。

### 上下文与成本启发：多模型串联要按重复读取计价
- LatComm（[2610.26840](http://arxiv.org/abs/2610.26840)）点出 'the receiving model processes all of its tokens again for every question'，并给出 'reduces the receiver's input by 57x and answers the questions of an article 3x faster'。凡是我们把同一份上下文喂给多个模型的场景，这笔重复计费都存在。
- 它的代价要记清：编码与读取两端都要冻结且能挂 cross-attention，'readable by a different LLM' 的泛化范围论文未给出，所以现在按趋势资产而非可落地方案对待。

### 评测方法启发：证据归因污染是通用失败模式
- VAG（[2610.26856](http://arxiv.org/abs/2610.26856)）形式化的 'privileged-correction contamination'——纠正信号的方向无法一致归因到特权证据时即为污染——不限于视觉。用强模型给弱模型做纠正的场景（RAG grounding、工具输出蒸馏）都应先问 '这条修正能被证据对比支持吗'。

### 长尾库启发
- FunCAD（[2610.26861](http://arxiv.org/abs/2610.26861)）的 'translates abstract requirements into candidate-specific physical tests' 可迁移为通用模式：当结果无法直接断言、但可被间接验证时，把抽象需求编译成候选相关的验证用例，再让反馈驱动迭代。
- CoopUQ（[2610.26852](http://arxiv.org/abs/2610.26852)）的 'cost penalizes navigation through regions predicted to be occupied or highly uncertain'——让不确定性显式进入代价函数而不是只停留在感知置信度——是可靠性工程里可复用的一招。
- Halcyon（[2610.26863](http://arxiv.org/abs/2610.26863)）以 '275× less pretraining compute' 和 'text-only pretraining does not improve T2I generation' 证伪了领域的默认前提，这类工作未来可能直接省下算力，保留在长尾库。
